# sharedd — публичная статистика, antiscan и общий порт

## Что нового

### 1. Публичная статистика карантина и трафика

На странице статистики появилась обезличенная таблица нод в Globalping-карантине. Полные IP-адреса и идентификаторы измерений в публичный API не попадают.

Публичный дашборд теперь показывает входящий, исходящий и суммарный трафик общих пользователей за сегодня, 7 и 30 дней. Счётчики сохраняются в SQLite и корректно переживают перезапуск или сброс метрик proxy.

***

### 2. Встроенный antiscan и единый порт

Node agent каждые 30 минут атомарно обновляет блок-лист `stamparm/ipsum` через `ipset` и применяет его к общему TCP-порту без TTL-фильтрации.

Порт задаётся регистратором через `shared_proxy.port` (по умолчанию `443`). Нода с несовпадающим локальным портом не допускается в master queue, а установщик прекращает обновление до замены binary.

***

### 3. Имя ноды при установке

Теперь при установке агента можно задать понятное имя ноды. Оно используется для её идентификации в пуле и помогает быстрее находить нужный сервер в панели, журнале и статистике.

Если имя не передано параметром, установщик предложит указать его интерактивно.

***

### 4. Установка без интерактивного ввода

Добавлены параметры для полностью неинтерактивной установки агента:

```bash
sudo bash pkg/install_full.sh \
  --registry https://ha.example.com \
  --name helsinki
```

| Ключ | Назначение |
|---|---|
| `--registry <URL>` | Адрес регистратора |
| `--name <имя>` | Имя ноды, 1..10 символов; итоговый ID `имя-xxxxx` |

Это удобно для автоматического развёртывания, cloud-init, Ansible, Terraform, шаблонов VPS и массового подключения серверов к пулу.

Пример установки через web-установщик:

```bash
curl -fsSL https://raw.githubusercontent.com/ugDeDe/sharedd/main/scripts/install_node_web.sh | sudo bash -s -- \
  --registry https://ha.example.com \
  --registry-token NODE_API_TOKEN \
  --name helsinki
```

## Исправления

### Агент сам запускается после смены IP

Исправлена ошибка, из-за которой агент мог не запускаться самостоятельно после смены IP-адреса ноды.

Теперь агент отслеживает смену адреса и корректно запускается сам. После регистрации с новым IP нода возвращается в обычный цикл проверок и, если проходит health-check, снова участвует в пуле без ручного вмешательства.

Это особенно важно для нод, где IP меняется автоматически или оператор заменяет адрес после подтверждённой блокировки.
