# specs/node-stats.md — категории статистики + графики (node-detail)

Страница: `ui/pages/cabinet/node-detail.ts` (+ `page.css`, `api.ts`).
Данные: `GET /api/me/nodes/{id}/detail` (формы — `api.ts`; сняты с
`registry/internal/server/node_detail_api.go`).
Авторитет по токенам/копирайту/a11y — `DESIGN.md` §3–§13. Здесь — только
категории, графики и пробелы бэкенда.

Требование владельца (RU): «как в mtplane по категориям раздели всю
статистику, графики нарисуй. График me writers не нужен».

## 2. Графики: подробная спека

Общий контейнер каждого графика (разметка, повторяемая):

```
<div class="chart-wrap" role="img" aria-label="<русская подпись>">
  <svg class="chart-svg" viewBox="0 0 100 26" preserveAspectRatio="none" aria-hidden="true">…</svg>
</div>
<table class="sr-only"><caption>…</caption><thead>…</thead><tbody>…</tbody></table>
<div class="chart-legend" aria-hidden="false">…<button>…</button></div>   <!-- только multi-series -->
<p class="card-note">…неполные/пустые данные…</p>
```

### График A — «Доступность, 7 дней»
- **Тип:** столбики (bar), по одному на день.
- **Источник:** `availability.daily[]`.
- **Серия/значение:** `ok_pct` (0–100 %), одна серия.
- **Ось Y:** 0–100 %, подписи min/max. **Ось X:** `date` → `dd.mm`.
- **Цвет:** класс здоровья дня — `ok` ≥99, `warn` ≥95, `bad` <95
  (переиспользовать `.day-bar-fill.ok|warn|bad`; функция `availColor`).
- **Легенда:** не нужна (одна серия); рядом заголовок «По дням, N дней».
- **Fallback:** `sr-only`-таблица `День | ok % | tcp ok/total | отчёты ok/total`.
- **Состояния:** пусто (`daily.length < 2`) → `dim`-текст «накапливается —
  пока мало точек»; loading — `skel-block`; partial — столбики есть, но
  дней меньше `window_days` → note «данные за N из 7 дней».
- **Бэкенд:** нет. **Data-ready: да.** (Текущий `day-bars` — уже это; апгрейд
  до единого SVG-компонента + sr-only-таблица.)

### График B — «Проверки» (окно)
Статус: **не рисуется в этой итерации** как отдельный период-переключаемый
график — данные есть, но окно фиксировано бэкендом (см. §3). Рекомендуется
свести «Последние проверки» к таблице сейчас, а мульти-серийный график B
подключить после появления `window`-параметра. Спека ниже — на будущее.

- **Источник (когда включим):** `availability.tcp_hist[]`, `gp_hist[]`,
  `report_hist[]`.
- **Серии:** TCP `ok`→0/100; GP `ratio`→%; Отчёт `metrics_ok`→0/100.
- **Ось Y:** 0–100 %. **Ось X:** `at` (время).
- **Легенда:** 3 кнопки-переключателя видимости серий, подпись «цвет + текст».
- **Fallback:** `sr-only` таблица `Время | TCP | GP | Отчёт`.
- **Data-ready: да** (по точкам), **окно/period-segment: нет** (blocked §3).

### График C — «Соединения, 24 ч» (заменяет writers-график)
- **Тип:** линия.
- **Источник:** `connections_24h.series[]`.
- **Серия:** **только `clients`** (соединения). Поле `writers` исключено
  полностью — `ponytail: writers chart удалён по требованию владельца`.
- **Ось Y:** число (min 0, max = max(clients) с запасом). **Ось X:** `at`.
- **Легенда:** не нужна (одна серия); подпись «Соединения по отчётам».
- **Разрыв линии** на пропуске сэмпла — `stroke-dasharray` не нужен, просто
  разрыв (как mtplane «разрыв = нет сэмпла»), note рядом.
- **Fallback:** `sr-only` таблица `Время | Соединения`.
- **Состояния:** `<2` точек → `dim`; `null` → `.table-empty`.
- **Бэкенд:** нет. **Data-ready: да** (поле `clients` уже в ответе).

### График D — «Хостинг: CPU / RAM / сеть, N ч»
- **Тип:** линия, multi-series.
- **Серии:** CPU %; RAM %; Сеть in; Сеть out (в байтах/с или в «всего за
  интервал» — уточнить единицу у бэкенда).
- **Ось Y:** две шкалы невозможны в простом SVG → приводим CPU/RAM к % (left)
  и сеть к производному % от max (note «сеть — относительно максимума») ИЛИ
  два отдельных мини-графика (CPU/RAM … %, сеть … байты). Рекомендация: две
  панели, чтобы не смешивать единицы.
- **Legend:** 4 серии, кнопки видимости.
- **Fallback:** `sr-only` таблица `Время | CPU | RAM | In | Out`.
- **Бэкенд:** **НЕТ СЕРИИ.** Сейчас приходят только текущие
  `cpu_percent`, `ram_percent` и накопительные `net_*_bytes_total`.
- **Data-ready: НЕТ (blocked).** Пока рисуем только плитки текущих значений
  + note «история появится после включения сбора на бэкенде».

### График E — «Уникальные IP по пользователям, 24 ч»
- **Сейчас (data-ready вариант):** горизонтальные столбики по пользователям,
  значение — `users.unique_ips_by_user[].unique_ips` (**текущий снимок**).
  Заголовок честный: «Уникальные IP по пользователям (сейчас)» — без «24 ч»,
  т.к. это не временной ряд.
- **Fallback:** `sr-only` таблица `Пользователь | Уникальных IP`.
- **Бэкенд:** для настоящего графика «24 ч» (тренд по времени) нужна серия
  (§3). **Data-ready как bar: да. Как 24-ч тренд: НЕТ.**

### График F — «Трафик по пользователям, 24 ч»
- **Сейчас (data-ready вариант):** сгруппированные столбики по пользователям:
  принято / отдано, значения — `users.traffic_by_user[].ingress_bytes`,
  `.egress_bytes` (24-ч **итоги**, не временной ряд).
- **Legend:** «Принято» / «Отдано» (2 серии), кнопки видимости.
- **Fallback:** `sr-only` таблица `Пользователь | Принято | Отдано`.
- **Бэкенд:** для «24 ч» как временного ряда (stacked area по часам) нужна
  серия (§3). **Data-ready как bar-итоги: да. Как тренд: НЕТ.**

### Плитки-сводки (не графики)

| Где | Значения (источник) |
|---|---|
| §3 Доступность | `overall_pct`, `gp_verified_pct` (+ `reports_ok/total`, `gp_checks_total`) |
| §6 Соединения | `current_user_connections`, `current_unique_ips` |
| §7 Хостинг | `cpu_percent`, `ram_percent`, `net_ingress_bytes_total`, `net_egress_bytes_total` |
| §8 telemt | кол-во метрик в снимке, `collected_at`, кол-во DC, суммарное `available_endpoints` |

| # | Что | Нужное поле / серия | Гранулярность | Окно | Включает график |
|---|---|---|---|---|---|
| G1 | История хостинга (ведущий gap) | `hosting.history[] = {at, cpu_percent, ram_percent, net_ingress_bytes, net_egress_bytes}` | 1–5 мин | 6 ч / 24 ч / 48 ч | D |
| G2 | Уникальные IP по пользователям во времени | `users.unique_ips_series[] = {at, user, unique_ips}` | 1 ч | 24 ч | E (тренд) |
| G3 | Трафик по пользователям во времени | `users.traffic_series[] = {at, user, ingress_bytes, egress_bytes}` | 1 ч | 24 ч | F (тренд) |
| G4 | Переключатель периода проверок | `?window=1d|7d|30d` на `/detail` (или отдельный `…/checks?window=`) — сейчас окно фиксировано | — | — | B (period-segment) |
| G5 | Сеть: дельта вместо накопленного | `net_*_bytes_delta` за интервал (иначе строим из G1) | как G1 | как G1 | D |

Замечания к текущим данным (не gaps, но ограничения):
- `availability.daily` — ровно 7 дней; окно не настраивается → period-segment
  только через G4.
- `report_hist` / `tcp_hist` / `gp_hist` — «bounded кольцом»
  (`node_detail_api.go:437`), длина переменная, окно фиксировано.
- `connections_24h.series` строится из `report_hist` — 24-ч линия `clients`
  готова; поле `writers` игнорируется.
- `telemt.metrics_snapshot`, `control_api.dcs` — только последний снимок.

## 4. Реализация графиков — рекомендация

**Ванильный inline-SVG, без зависимостей.** Вынести `spark()` в
`ui/lib/chart.ts`: `lineChart(pts[], opts)` и `barChart(items[], opts)`,
возвращающие строку SVG.

Обоснование:
- В сборке sharedd **нет npm**: `tools/uigen` — Go-embedded esbuild бандлит
  `ui/**`; `node_modules` отсутствует, добавлять туда нельзя.
- Вендорить `chart.umd.min.js` (как mtplane) = ~200 КБ в `webassets` + loader,
  и это новый бинарный артефакт в репо ради 7–31 точки.
- SVG уже принят: `.metric-spark` в `node-detail.ts` — тот же паттерн.
- SVG бесплатно даёт `sr-only`-таблицу как текстовый эквивалент и CSP-safe
  (нет canvas-eval). Интерактив (zoom/tooltip) спекой не требуется.

Файлы, которые создаст @frontend (не в этой фазе): `ui/lib/chart.ts`;
правки `node-detail.ts`, `page.css` (раскладка `.chart-wrap`, `.chart-svg`,
`.chart-legend`), `ui/components/misc.css` (`.sr-only`).

## 5. Что заменяет удалённый график «me writers»

Раздел **не удаляется целиком** — удаляется **серия**. Бывшая карточка
«Соединения 24ч» сейчас рисует `spark(series.map(p => p.writers))`. После
изменения:

- `writers` больше **не участвует** ни в одном графике.
- Тот же график рисует `clients` (**График C**, §2).
- Плитки карточки теперь показывают только `current_user_connections` и
  `current_unique_ips`; строка «Писатели (сейчас)» (`current_writers`)
  убирается из видимой части.
- Значение `writers` остаётся доступно только внутри свернутого снимка
  telemt (`metrics_snapshot`), если окажется там — это сырой JSON, не график.

Итог: «me writers» как график и как метрика в UI **отсутствует**; категория
«Соединения» заменяет его линией соединений (`clients`).

## 6. Доступность графиков (итог, дублирует DESIGN.md §13.4)

Для **каждого** графика A–F:
1. Контейнер `role="img"` + русский `aria-label`.
2. `<table class="sr-only">` с `caption`/`thead`/`tbody` и теми же значениями
   (те же форматтеры `fmtPct`/`fmtBytes`/`fmtClock`).
3. Multi-series — видимая легенда «цвет + текст» через `<button>`; переключение
   серий по клавиатуре, `aria-pressed`.
4. `.sr-only` отсутствует в sharedd → добавить в `ui/components/misc.css`.
5. Пусто/мало точек — текст, не пустой SVG.
6. Цвет состояния (ok/warn/bad) дублируется текстом (подпись/`title`), не
   только цветом.

## 7. Проверка (для @frontend, минимальная)

- `bash scripts/build_ui.sh` собирается без npm.
- Каждый из графиков A/C/E/F присутствует и имеет `role="img"`,
  `aria-label` и `sr-only`-таблицу.
- В DOM нет строки `writers` ни в одном SVG/плитке видимой части.
- `git grep -n "writers" ui/pages/cabinet/node-detail.ts` → 0 совпадений в
  разметке видимых секций.
