# Форма создания облачного ресурса — каталог, оценка, профиль установки

Статус: реализовано (UI). Бэкенд (catalog/estimate) реализуется параллельно по тому же
FROZEN-контракту; до его деплоя форма работает против моков/живых 501/504.

## Что изменилось

Форма `#cr-form` (Хостинги → Ресурсы → «Создать ресурс») больше не собирает конфигурацию
сырыми текстовыми полями. Все значения приходят из живого каталога провайдера.

### 1. Каталог (GET /api/me/hosting-connections/{id}/catalog)

- `Локация` — select `code · name` из `locations[]`; смена локации перезапрашивает
  каталог с `?location=CODE` (гасится последовательным номером `CR_CAT_SEQ`).
- `ОС` / `Тип диска` — select из `os[]` / `disk_types[]` (`id` → `name`).
- `CPU` — select из `cpu_models[]` (строка уходит в `configuration.cpu`).
- `Ядра` / `ОЗУ` / `Диск` — number-поля с `min`/`max` из `limits.{cores,ram_gb,disk_gb}`
  + клиентский clamp на вводе + подсказка «доступно X–Y».
- `Период` — статичный select `1d|3d|1w|1m|3m|6m|1y` (по умолчанию `1m`).
- `Скорость сети` — select из `network.speeds`, заблокирован, пока локация не выбрана
  (network приходит только вместе с location). `network.available=false` → поле
  «Скорость не настраивается».
- `limits.types.VPS === false` → баннер «создание недоступно», submit заблокирован.
- Пока каталог грузится: скелетон + заблокированный submit. Ошибка каталога: баннер
  с «Повторить». Beget-подключение (501) → прежний баннер-редирект на legacy-визард.
- Смена подключения в `#cr-conn` перезагружает каталог.

### 2. Оценка цены (POST /api/me/cloud-resources/estimate)

- Debounce 600 мс на любой ввод конфигурации; запрос, когда `cores/ram/disk/location`
  валидны. Каталог не требуется: цена пересчитывается даже при медленной/упавшей
  перезагрузке региона.
- Перезапуск оценки: после завершения `applyCrCatalog(location)` (смена региона),
  смены подключения, профиля, периода, скорости и остальных полей конфигурации.
- 200 → баннер `≈ 2.12 USD за 1m (30 дн.) · регион NL`; регион берётся из текущего
  значения `#cr-loc`, поэтому подпись всегда соответствует выбранной локации.
- 501 (beget) → баннер скрыт; 502/504 → «Цена недоступна (провайдер не ответил)…».
- Никогда не блокирует submit — цена информационная.

### 3. Профиль установки (fieldset «Установка»)

- `Профиль` — select из `textProfiles()` (те же `published` + свои ТЕКСТОВЫЕ профили,
  что в визарде и модалке установки; graph отфильтрован). Нет профилей → подсказка
  со ссылкой на `#/profiles`, установка остаётся необязательной.
- `Версия` — select `vN…v1` (последняя известная порядковая из `OwnProfile.versions`).
  Значение резолвится через `readVersion()`/`knownVersion()` (последняя версия уже
  в кэше после `hydrateOwn`); хранится PK `profile_version_id`.
- Чекбокс «Установить сразу после создания» — включается и ставится ON при выборе
  профиля, сбрасывается при «— без профиля —».
- `renderInstallVars` (mountVars + `vars_schema` выбранной версии) показывается,
  когда версия загружена.

### 4. Флоу отправки

`create` (Idempotency-Key, как раньше) → 202/ack → опрос ресурса (`pollResourceState`)
→ по готовности И включённом чекбоксе →
`POST /api/me/cloud-resources/{id}/install {profile_version_id, vars}` →
опрос операции (`pollInstallOp`, 5 мин) → карточка ресурса показывает
`Создание → Установка → Готово` (переиспользованы `.wizard-steps`).

- Ошибки установки показываются баннером на карточке ресурса и НЕ ломают созданный
  ресурс (повтор — штатная кнопка «Установить профиль»).
- Без мгновенной установки форма закрывается сразу (прежнее поведение).
- Модалка ручной установки `doInstallRes` переведена на тот же контракт
  `{profile_version_id}` (PK последней версии из кэша).

## Правка по прод-фидбеку (форма создания)

- `#cr-name` / `#cr-hostname` больше без `.mono` — как обычные поля имени в визарде.
- `CPU` заблокирован с подсказкой «Выберите локацию» до выбора локации; каталог
  с `?location=` наполняет `cpu_models` (фильтр на бэкенде), затем select включается.
  Скорость сети с одним значением предвыбирается; пустая скорость не попадает в
  `configuration.networkSpeed` (поле DTO `networkSpeed?`) и не блокирует submit.
- `#cr-count` («Количество», 1–20, default 1). При >1 имена получают суффикс
  `-01…-NN` (hostname — тоже, если задан). Создание последовательное: на каждый
  элемент свой `Idempotency-Key`, 202 → poll до ready; ошибка элемента пишется
  в список и пачка продолжается. «Установить сразу» ставится также последовательно;
  сбой установки не отменяет созданный ресурс. Кнопка заблокирована до конца пачки,
  финал — «Создано X/N»; список `#cr-batch` показывает бейджи по элементам.
- Оценка при count>1: сумма за 1 шт. × N считается на клиенте и подписывается
  «за 1 шт.».

Проверка: `npx tsc --strict` по `ui/pages/cabinet/main.ts` + `bash scripts/build_ui.sh`.

## Правка по прод-фидбеку (статус, SSH, «Серверы»)

- **Готовность = `state==="ready"` И непустой IP.** `crMetaFor/resReady` — единый
  источник для карточек, пачки, poll'ов и «Ресурсов у провайдера». `ready` без IP
  показывается как «создаётся · ожидание IP…»; «готов» без IP не существует.
- **Ошибки:** бейдж «Ошибка» + причина из `last_error` (`insufficient_funds` →
  «Недостаточно средств», `forbidden`, `validation_failed`, `provider_timeout`,
  `no_ip` → «Провайдер не выдал IP», `worker_busy`, `credentials_unavailable`,
  иначе — исходный код). `error`/`deleted` — терминальные для опроса.
- **«Проверить SSH»** на готовых карточках → `POST /api/me/cloud-resources/{id}/check`
  (`{ssh_ok,error}`); во время запроса — спиннер, результат инлайн (ok / fail+причина).
  409 `not_ready|ssh_unavailable` и 501 `not_implemented` маппятся в те же причины.
- **«Серверы» → «Ресурсы у провайдера»:** карточки в стиле своих серверов
  (label/provider/state/IP, действия Проверить SSH / Установить / Сменить IP /
  Удалить, для `planned|error` — «Убрать запись»). Шаги установки — `stepsHTML`
  по операции `active_operation_id` из `GET /api/me/operations`; опрос 5 с.
- **Форма:** `cr-name` (maxlength 64), `cr-count`, `cr-hostname` повторяют
  разметку/атрибуты `sv-label`/`sv-port`/`sv-user`; `.mono` и inline-стили убраны.
- **Пачка:** продолжается после ошибки элемента, причина — в строке; итог
  «Создано X, ошибок Y», кнопка показывает честный итог (не «готово X/N»).

## Правка по UX-фидбеку (оценка, удалённые, статус)

- **Оценка явно называет регион:** `≈ … за 1m (30 дн.) · регион NL`; регион — текущий
  `#cr-loc`, поэтому после смены локации подпись не врёт. Оценка перезапускается в
  конце `applyCrCatalog` (ветка с location), при смене подключения, профиля, периода,
  скорости и полей конфигурации. `crConfigForEstimate` больше не ждёт каталога.
- **Удалённые скрыты в обоих списках:** `visibleCres()` фильтрует `state==="deleted"`
  в «Хостинги → Ресурсы» и «Серверы → Ресурсы у провайдера», включая счётчики и
  empty-state (defensive, пока бэкенд не отфильтровал).
- **Статус важнее state:** `planned|creating` с непустым `last_error` рендерится как
  «Ошибка» с причиной (`crFailed/crReasonOf`), действия — «Заменить»/«Убрать запись»,
  IP-строка — «IP не получен» вместо «ожидание IP». В пачке причина с бейджем
  «ошибка» также перекрывает «создаётся · ожидание IP…».
- **Честное ожидание:** `creating` без IP и без ошибки по-прежнему
  «создаётся · ожидание IP…».
- Проверка: `npx tsc --strict` по `ui/pages/cabinet/main.ts` + `bash scripts/build_ui.sh`.

## Правка: лимиты имени ноды (NAME-HASH)

- **`#cr-name`:** `maxlength=10`; help «1–10 символов: латиница, цифры, . _ - (без
  . _ - по краям). Отображается как имя ноды NAME-HASH.»; инлайн-ошибка
  `#cr-name-err` (`aria-invalid`, `aria-describedby`). Регэксп
  `^[A-Za-z0-9](?:[A-Za-z0-9._-]{0,8})?[A-Za-z0-9]$` — 1..10, без пунктуации по краям.
- **Пачка:** суффикс `-NN` — 3 символа, поэтому база ограничена: count 2–9 → ≤7,
  10–20 → ≤6. Ошибка: «Для N ресурсов имя должно быть не длиннее X символов
  (суффикс -01…-NN).» Имена элементов пачки строятся из уже провалидированной базы.
- **Submit:** `crNameError()` вызывается до любого API-запроса (одиночный и пачка);
  `runCrBatch` получает только валидную базу. Hostname не ограничивается длиной —
  он не попадает в node ID.
- Проверка: `npx tsc --strict` по `ui/pages/cabinet/main.ts` (чисто) +
  `bash scripts/build_ui.sh`.

## Правка: сверка с хостингом (provider_reconcile_required)

ФРИЗ-контракт (бэкенд параллельно): `POST /api/me/cloud-resources/{id}/reconcile`
(CSRF) → `200 {"resolved":"absent"}` (ресурс станет deleted) | `200
{"resolved":"found","external_id"}` | `409 provider_reconcile_required`.

- **api.ts:** `CloudReconcileResult` + `api.reconcileCloudResource(id)` (POST `{}`,
  CSRF добавляет `req`).
- **Причина в карточке:** `provider_reconcile_required` в `CR_REASON` → «Платный
  исход операции неясен — сверьте ресурсы с хостингом» (узнаваем и в
  planned/creating с `last_error`, и в error).
- **Кнопка «Сверить с хостингом»:** `crReconBtn(r)` — на любой ошибочной строке
  (`crFailed`) и на строках, где сверку затребовал delete-path (`CR_RECON[id]`).
  Показывается в обеих карточках: «Ресурсы» и «Ресурсы у провайдера» в «Серверах».
  Состояние `CR_RECON: {busy?, hint?}`: busy — disabled «Сверка…».
- **`reconcileResource(r)`:** absent → тост «Хостинг подтвердил: сервера нет,
  запись удалена», refetch (запись исчезнет из списков); found → тост «Найден на
  хостинге: привязан (IP обновите опросом)», refetch; `409 provider_reconcile_required`
  → инлайн-подсказка «На аккаунте есть несвязанные серверы — проверьте вручную на
  Nodehost» (`crReconHTML`, класс `cr-check bad`), без повторов/циклов; прочие
  ошибки — тост с маппингом `CR_REASON`.
- **Delete-path:** в `confirmDeleteRes` при `e.code === "provider_reconcile_required"`
  вместо тупикового error-тоста — модал закрывается, на карточке появляется та же
  кнопка + подсказка; обычное удаление не тронуто.
- Проверка: `npx tsc --strict` по `ui/pages/cabinet/main.ts` (чисто) +
  `bash scripts/build_ui.sh` (cabinet.html пересобран).
