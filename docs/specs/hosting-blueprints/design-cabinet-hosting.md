# Design — «Хостинги» и облачные ресурсы в кабинете

**Артефакт для реализации (`@frontend`). Дизайн, не код.**
Парный документ (per-component): [`specs/cabinet-hosting-ui.md`](specs/cabinet-hosting-ui.md).
Стадия реализации, к которой привязываемся: stage-04 (hosting-connections),
stage-05 (cloud resources + node management), stage-06 (cloud install).

Авторитетные источники (только они):

- `03-cabinet-api.md` §3–§5 — маршруты/DTO; §7 — таблица отказов.
- `implementation-stage-04-storage-api.md` — фактический hosting API (501 catalog,
  `Balance`-в-Connection, min-interval 60s).
- `implementation-stage-05-cloud-management.md` — фактический cloud API
  (`cloud_resources2`, `management` PUT manual, async worker, отклонения M2/M3).
- `implementation-stage-06-cloud-install.md` — install-маршрут и типы SSH-гейтов.
- `04-storage-and-execution.md` §5.1 — расширенный набор состояний.
- `DESIGN.md` — **токены, классы, копирайт, доступность. Правки ниже ему не
  противоречат и не вводят ни одного нового цветового токена.**
- `ui/pages/cabinet/{index.html,page.css,api.ts,main.ts,node-detail.ts}`,
  `ui/components/*.css`, `ui/lib/*` — существующие паттерны.

## 1. Направление дизайна

**Сохраняем существующую систему.** Хостинги — это операторская панель внутри
уже существующего кабинета: те же `.card`, `.node-card`, `.badge`, `.table-cards`,
`.modal`, `.field`, `.banner`, `.empty-state`, `.skeleton`, `#toast`. Ни одной
новой кнопки, поля, бейджа или цвета. Новый CSS страницы — **только раскладка**
(сетки/отступы), по правилу нулевого дублирования из `DESIGN.md` §1.

Принципы:

1. **Правда о состоянии вместо успеха.** Асинхронные команды (create/delete/
   install) не показывают «готово», пока ресурс не дошёл до `ready`/`deleted`
   по опросу. `pending` в ack — это «принято», не результат (03 §2.1).
2. **Один primary на секцию** (`DESIGN.md` §2.2). В «Подключениях» primary —
   «Добавить подключение»; в «Ресурсах» — «Создать ресурс».
3. **Отказ ≠ пересоздание** (`DESIGN.md` §8) — инвариант присутствует на экране
   ресурсов, в баннере бана и в подтверждениях delete/replace.
4. **Секреты не возвращаются** (`DESIGN.md` §9). Пароли/ключи — `type=password` +
   `.input-group .in-btn[data-reveal]`; после отправки поле очищается; ни один
   read-эндпоинт не отдаёт plaintext, и UI его не рисует.
5. **409/422/501 — не ошибка связи, а состояние.** Их не показываем тостом
   «не удалось»; показываем конкретный русский текст и, где возможно, кнопку
   исправляющего действия (обновить, повторить безопасно).

## 2. Информационная архитектура

Верхний пункт навигации **«Хостинги»** (существующий `#/beget`, ключ маршрута
`beget` — **не переименовываем**, чтобы не трогать роутер и мобильную панель)
превращается из одной legacy-формы Beget в раздел с двумя сегментами:

| Сегмент | Содержимое |
|---|---|
| **Подключения** | Список подключений (провайдер `nodehost\|beget`): карточка на подключение, метка, бейдж verified, бейджи возможностей, баланс + свежесть, действия. Кнопка «Добавить подключение». Legacy-форма Beget здесь остаётся как частный случай провайдера `beget`. |
| **Ресурсы** | Список управляемых облачных ресурсов, создание (nodehost), install/change-ip/replace/delete. У Beget — явное состояние «пока недоступно (501)» со ссылкой на legacy VPS-поток. |

Переключение сегментов — существующий компонент `.nd-tabs` (role="tablist",
roving tabindex), активный сегмент в хэше `#/beget?tab=conns|resources`
(как `node-detail.ts` пишет `?tab=`). По умолчанию — `conns`.

> ponytail: не заводим третий навигационный пункт и не переименовываем маршрут.
> Если раздел разрастётся — вынести «Ресурсы» в отдельный `#/hosting` отдельной
> задачей; сейчас хватает одного пункта и сегментов.

**Детальная карточка ноды** (`node-detail.ts`) дополняется панелью **«Управление»**
(между «Действия» и остальными) — см. §5 спеки.

## 3. Раскладка

### 3.1 «Подключения» (список)

```
#view-beget
├─ .nd-tabs#hosting-tabs                (Подключения · Ресурсы)
├─ [data-hpanel="conns"]
│  ├─ <section class="card">
│  │  ├─ .card-head  h2 «Подключения» · .hint · .btn.primary «Добавить подключение»
│  │  ├─ .node-list#hosting-conns       ← карточки подключений (.node-card.hc)
│  │  └─ .card-note                      ← пояснение про секреты и 60-секундный min-interval баланса
│  └─ (пусто → .empty-state внутри #hosting-conns)
└─ [data-hpanel="resources"] hidden
   ├─ <section class="card">  список ресурсов (#cloud-res-list) + «Создать ресурс»
   └─ <section class="card">  (форма создания, hidden по умолчанию)
```

При > 0 подключений — не модалка добавления «на старте», а обычная кнопка.
Список — вертикальный (`.node-list`), не карточная сетка: приватность/скан
и действий важнее плотности.

### 3.2 Карточка подключения — `.node-card.hc`

Переиспользуем структуру `.node-card` (grid `1fr auto`), но **отключаем
курсор-указатель и клик-роутинг** (у карточки нет `data-id`; добавляем
`.node-card.hc { cursor: default; }` и toggle-details по кнопке):

```
article.node-card.hc                    data-conn="{id}"
├─ .node-main
│  ├─ .node-top
│  │  ├─ .node-id            «{label}»                (не .mono — это метка)
│  │  ├─ .badge.mono         «nodehost» | «beget»
│  │  └─ .badge             verified: .ok «подключён» | нейтр. «не проверен»
│  ├─ .node-sub
│  │  ├─ .badge.info/.badge/.badge.warn  возможности: .badge.ok «создание»/«смена IP»/«удаление», отсутствующая — .badge (нейтр., title «недоступно»)
│  │  ├─ span «баланс» + span.mono amount currency
│  │  └─ .badge fresh/stale/unavailable + «{age}»
│  └─ .node-problem (только при error.code) — безопасный код не показываем текстом, показываем русскую причину
├─ .node-side
│  ├─ .btn.sm «Обновить баланс»      data-hcbalance
│  ├─ .btn.sm «Проверить»            data-hcverify
│  ├─ .btn.sm.ghost «Изменить»       data-hcedit
│  └─ .btn.sm.danger «Удалить»       data-hcdel
└─ .node-more (toggle, class .open)
   └─ .kv-пары: revision, credential_revision, verified_at, checked_at, last_attempt_at, scope, id
```

Баланс (`.node-sub`):

| freshness | Бейдж | Класс | Значение |
|---|---|---|---|
| `fresh` | «актуален · {age}» | `.badge.ok` | `{amount} {currency}` (`.mono`), иначе «сумма не указана» |
| `stale` | «устарел · {age}» | `.badge.warn` | старый `amount` + подпись «последнее успешное значение» |
| `unavailable` | «недоступен» | `.badge` (нейтр.) | «—» |

`amount === null` при `fresh` — честно «сумма не указана» (никогда 0).
`error.code` при `stale`/`unavailable` → текст в `.node-problem`:
`provider_error`→«Провайдер вернул ошибку», `provider_timeout`→«Таймаут провайдера»,
`credentials_unavailable`→«Учётные данные недоступны», иначе — серверный
`message`, если он есть (сервер отдаёт безопасный русский текст).

### 3.3 Карточка ресурса — `.node-card.cr`

```
article.node-card.cr                    data-res="{id}"
├─ .node-main
│  ├─ .node-top
│  │  ├─ .node-id          «{label}»
│  │  ├─ .badge.mono       «nodehost» | «beget»
│  │  ├─ .badge {state}     состояние (см. таблицу ниже)
│  │  └─ .badge            «замена» при replaced_by / «заменён» при replaces
│  ├─ .node-sub
│  │  ├─ IP моно: .mono ip / «—»
│  │  ├─ нода: a.node-open href="#/nodes/{node_id}" .mono  | «—»
│  │  └─ подключение: label связи (если известна)
│  └─ .node-problem        last_error безопасного кода операции
├─ .node-side   (кнопки зависят от state, см. §spek 7)
└─ .node-more   активная операция (чип + состояние + ссылка «К операциям»), replaces link
```

Состояния ресурса (маппинг `.badge`):

| state | Бейдж | Класс | Примечание |
|---|---|---|---|
| `planned` | «запланирован» | `.badge.info` | внутренний ID есть, провайдер ещё нет |
| `creating` | «создаётся…» | `.badge.info` | worker работает |
| `ready` | «готов» | `.badge.ok` | можно install/change-ip |
| `deleting` | «удаляется…» | `.badge.warn` | |
| `deleted` | «удалён» | `.badge` (нейтр.) | |
| `error` | «ошибка» | `.badge.bad` | показать `last_error` |
| (расширенные `installing`/`admission_pending`/`admitted`/`superseded`/`unknown`) | как есть | `.badge.info`/`.warn`/`.special` | **неизвестный state рисуем дословно** (паттерн уже принят в коде) |

### 3.4 Точки перелома

- `.node-card` уже переходит в одну колонку на ≤720px; `.node-side` там —
  `flex-wrap` с левым выравниванием (добавляем `.hc .node-side/.cr .node-side`
  в существующее правило `.srv .node-side`-стиля). Кнопки не переносятся
  под текст нечитаемо — переносим их строкой под карточкой.
- Форма создания ресурса — `.srv-grid` (auto-fit minmax(220px,1fr)), как форма
  сервера. На ≤720px — одна колонка.
- `.nd-tabs` уже скроллится по-горизонтали на узком.

## 4. Словарь состояний (единый для всех экранов хостинга)

| Понятие | Визуал | Источник |
|---|---|---|
| Подключение проверено | `.badge.ok` «подключён» | `verified_at != null` |
| Подключение не проверено | `.badge` «не проверен» | `verified_at == null` |
| Возможность есть | `.badge.ok` «создание» / «смена IP» / «удаление» | `capabilities.{create,change_ip,delete}` |
| Возможности нет | `.badge` + `title` | `capabilities.* == false` |
| Баланс актуален/устарел/нет | `.badge.ok/.warn/` нейтр. + возраст | `balance.freshness` |
| Ресурс создаётся | `.badge.info` «создаётся…» | `state=creating` |
| Ресурс готов | `.badge.ok` «готов» | `state=ready` |
| Ресурс удаляется | `.badge.warn` «удаляется…» | `state=deleting` |
| Ресурс в ошибке | `.badge.bad` «ошибка» | `state=error` |
| Операция выполняется | `.badge.info` + прогресс | `active_operation_id`/список операций |
| Блок IP (бан) | `.banner.info` (информ.) | событие `ip_blocked`/`node_terminated`; **не покупка** |
| Замена | `.badge.info` «заменяет #N» / `.badge` «заменён на #M» | `replaces_resource_id`/`replaced_by_resource_id` |
| Beget-облако недоступно | `.banner.info` | 501 `not_implemented` |

## 5. Копирайт (русский, операторский регистр — `DESIGN.md` §7)

**Заголовки и кнопки**

- Заголовок раздела — «Хостинги» (как в навигации). Сегменты: «Подключения», «Ресурсы».
- «Добавить подключение» (primary, раздел «Подключения»).
- «Проверить», «Обновить баланс», «Изменить», «Удалить» (карточка подключения).
- «Создать ресурс» (primary, раздел «Ресурсы»).
- «Установить профиль», «Сменить IP», «Заменить», «Удалить» (карточка ресурса).

**Пустые состояния** (`.empty-state`)

- Нет подключений: t «Подключений пока нет», s «Добавьте подключение к Nodehost
  или Beget — регистратор сможет создавать и обслуживать серверы прямо отсюда».
- Нет ресурсов: t «Ресурсов пока нет», s «Создайте ресурс на Nodehost — после
  готовности установите профиль, и нода появится в пуле».

**Инвариант «отказ ≠ пересоздание»** (обязателен, `DESIGN.md` §8) — `.card-note`
в разделе «Ресурсы»:

> «Ошибка создания, установки или бан IP не создаёт новый сервер автоматически.
> Ресурс остаётся и доступен для повторной установки. Платный заказ отправляется
> ровно один раз — повтор того же запроса не создаёт второй сервер.»

**Бан/диспозиция** (информационный `.banner.info` в карточке ресурса и на ноде):

> «IP в блокировке (ip_ban) — это вердикт регистратора, показан информационно.
> Он **не** запускает покупку или замену сервера: автопокупка при бане не
> выполняется. Замену можно инициировать только вручную.»

(Запрещены утверждения «пересоздаст», «заменит автоматически», «автовосстановление»;
отрицания этого же действия разрешены.)

**Beget-облако (501)** — `.banner.info` в разделе «Ресурсы» при подключении Beget:

> «Управляемое облако Beget пока недоступно. Создание и обслуживание серверов у
> Beget выполняются через прежний поток — [Создать сервер](#/create).»

**Ошибки провider/конфликтов** — показываем серверный `message` (он безопасный и
русский), а не переписываем. Если `message` нет, подставляем по коду:

|---|---|

| `provider_timeout` | «Провайдер не ответил вовремя. Повторите позже.» |

## 6. Доступность (WCAG 2.2 AA — `DESIGN.md` §10)

1. **Семантика.** Список — `<div role="list">`/`<article role="listitem">` либо
   `.node-list` (как есть). Действия — `<button type="button">`. Ссылка на ноду —
   `<a href="#/nodes/{id}">`. Сегменты — `<button role="tab">` внутри
   `role="tablist"`, `aria-selected`, `aria-controls`, roving `tabindex`.
2. **Метки полей.** Каждое поле — `<label for>`. Форма подключения: `provider`
   `<select>` с событием смены полей; `label` `maxlength=100`; секреты —
   `autocomplete="new-password"`. Код 2FA — `inputmode="numeric"`
   `autocomplete="one-time-code"`.
3. **Ошибки формы.** `.banner.bad[role="alert"]` внутри формы; фокус — на первое
   невалидное поле; парные правила Beget (cloud-пара обязательна; hosting-пара
   «всё или ничего») проверяются до отправки и подсвечиваются `aria-describedby`.
4. **Live-статусы.** Тост `#toast` уже `aria-live="polite"`. Дополнительно
   добавляем одиночный регион `<div id="hosting-live" class="sr-only"
   aria-live="polite" aria-atomic="true">` для прогресса операций
   («Ресурс pool-node: создаётся», «…: готов», «…: ошибка»), чтобы прогресс
   озвучивался без перевода фокуса.
5. **Фокус.** Модалки — существующий `openModal` с ловушкой фокуса и Escape
   (`main.ts`). После закрытия — возврат на кнопку-инициатор (уже реализовано).
   `renderSection` не сбивает фокус/скролл при опросе 5 с (уже реализовано).
6. **Не только цвет.** Бейджи — цвет **и** слово (`.badge i` + текст), свежесть
   баланса — ещё и возраст текстом.
7. **Клавиатура.** Все действия — Tab/Enter/Space. Карточки ресурса/подключения
   не требуют клика по строке: доступ к действиям — через явные кнопки.
   Сегменты — стрелки Left/Right/Home/End (как табы ноды).
8. **Реflow.** Без горизонтального скролла на 320px; форма в одну колонку ≤480px.

## 7. Motion

Motion — минимальный и утилитарный (это операторский инструмент, не витрина):

- Бейдж состояния `creating`/`deleting` — точка `.badge i` может пульсировать
  существующей `@keyframes pulse`; под `prefers-reduced-motion: reduce` — без
  анимации (уже покрыто в `topbar.css`).
- Смена сегмента — мгновенно, без анимации контента.
- Опрос (5 с) — `renderSection` (без визуального «мигания»), не crossfade-анимация.
- Никаких entrance-анимаций списков.

## 8. Что НЕ делаем

- Не добавляем цветовые токены, кнопки, поля, бейджи-варианты.
- Не переименовываем маршрут `#/beget` и не трогаем `VIEWS`/мобильную панель.
- Не рисуем оценки стоимости (`estimate`) — стадия-05 отдаёт 501 (§spek 10).
- Не создаём отдельный «облачный» навигационный пункт.
- Не показываем внешние ID провайдера как разрешение на действие (03 §4):
  delete/change-ip идут только по surrogate `resource_id`.

## 9. Обязательный QA-гейт реализации

После реализации `@frontend` **обязан** прогнать (это не опция):

```
/impeccable critique   — полный разбор экрана
/impeccable audit      — a11y, responsive, anti-patterns
```
