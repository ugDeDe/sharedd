## Data layer (`api.ts`)

- Helpers: `hostingConnections/create/update/delete/verify/refreshHostingBalance/hostingCatalog`,
  `cloudResources/cloudResource/createCloudResource/deleteCloudResource/changeCloudIP/replaceCloudResource/installCloudResource/estimateCloudResource/cloudIPOptions`,
  `nodeManagement/putNodeManagement`.
- `Idempotency-Key` sent on create/replace/delete/change-ip/install; `X-Confirm-Action: delete` on DELETE.
- Client keys are generated once per logical attempt (`newIdemKey()`), reused on retry, regenerated on `idempotency_conflict` / new form open.
- No secrets in types: credential bundles are write-only (`hostingConnections` read model has no plaintext).

## QA gate

`/impeccable critique` + `/impeccable audit` + `/impeccable polish` executed as a structured manual pass
(the skill's nested `reference/*.md` files are blocked by the environment's `~/.config/**` deny rule; the
skill's General rules, `DESIGN.md`, and the spec were the reference). Fixes applied from the pass:

- Resource cards previously had an unreachable `.node-more` (no toggle) → added `data-crtoggle` + `OPEN_RES` set with keyboard-reachable «Детали/Свернуть».
- Create-form close now returns focus to «Создать ресурс» instead of a hidden submit.
- Stale progress banner cleared on terminal `error`.

Audit results: segments are full APG tablist (roving tabindex, Arrow/Home/End, `aria-controls`/`aria-selected`);
rows are `role=list/listitem` with `aria-labelledby`; badges are text+colour; secrets `autocomplete=new-password`;
2FA `inputmode=numeric`+`one-time-code`; mutating buttons `type=button` and disabled in-flight; `#hosting-live`
is `aria-live=polite aria-atomic`; polling uses `renderSection` (no focus/scroll steal); ban note is
`.banner.info[role=note]`. No new colour/radius/shadow/animation rules; no banned patterns introduced.

## Deviations (documented)

- `balance.checked_at/last_attempt_at` typed `number` (unix seconds), not `string`; `balance.error` is `{code}` (backend shape).
- `CloudResource` DTO has **no** `last_error` → resource `.node-problem` cannot show a resource-level provider error; provider codes surface via balance and the operations journal.
- `GET …/{id}/ip-options` and `/estimate` are not mounted (501) → not called; the change-IP subnet stays a free `type=number` input, `#cr-estimate` stays hidden.
- `change-ip` returns **200 CloudResource** (impl); the 202 ack path is also handled (poll until IP changes).
- `PUT …/management` ignores `process_current_ban` server-side (manual body carries only mode+revision); UI still sends it (forward-compatible). `active_run_id` is not returned → shown «—».
- `replace` requires `configuration` and the stage-06 backend ignores optional profile/vars; UI sends them forward-compatibly but does not present a post-replace install.
- Node `actions` panel link to operations goes to `#/operations` without `HIGHLIGHT_OP` (avoids cross-module state coupling).
- `PRODUCT.md` is absent; no `PRODUCT.md` was created (out of the task's file scope). Register treated as product/tool per `DESIGN.md`.
