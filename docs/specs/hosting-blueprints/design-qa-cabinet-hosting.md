## 2. Defects found

### D-01 — FAIL (fixed). Details toggle unreachable on connection & resource cards
`ui/pages/cabinet/main.ts` — `connCardHTML()` (was L1002–1010) and
`resCardHTML()` (was L1336–1343).

The `data-hctoggle`/`data-crtoggle` «Детали/Свернуть» buttons were rendered
**inside** `.node-more`, which is `display:none` until `.node-card.open`
(`ui/components/nodecard.css` L51–56). There is no card-level click for
`.hc`/`.cr` cards (the only delegated card click is `.node-card[data-id]`,
L2561/L2570, and hc/cr cards carry no `data-id`). Result: the disclosure button
was hidden before the card was open and could never be activated — the
connection/resource detail (`revизия`, `credential_revision`, `external_id`,
`replaces` links) was **unreachable by mouse and keyboard**. This contradicts the
implementation summary's claim that the resource toggle was made reachable.

**Fix applied (presentation only, behaviour-preserving):** moved the toggle into
the always-visible `.node-side` cluster and gave the panel an id + `aria-controls`:
`data-hctoggle`/`data-crtoggle` now sit in `.node-side` with
`aria-expanded` + `aria-controls="hc-more-{id}|cr-more-{id}"`; `.node-more`
gained `id="hc-more-{id}|cr-more-{id}"`. Focus survives re-render via
`renderSection`'s stable-selector restore (`[data-hctoggle="N"]`).

### D-02 — Medium a11y (fixed). `role="list"` containers had non-`listitem` children
`ui/pages/cabinet/main.ts` `renderConnections()`/`renderResources()` and
`ui/pages/cabinet/index.html` (initial skeletons, L189/L238).

`#hosting-conns` / `#cloud-res-list` are `role="list"` (spec §2/§21), but their
loading (`.skeleton`), empty (`.empty-state`) and error (`.banner.bad[role=alert]`)
children were plain divs — an axe `aria-required-children` violation for
`role=list` in every non-loaded state.

**Fix applied:** every direct child is now a `role="listitem"` — the empty-state
carries `role="listitem"`, the error banner is wrapped in `<div role="listitem">`,
and the initial skeletons are wrapped in `<div role="listitem">`. `role="list"` /
`role="listitem"` on loaded cards (spec §21) preserved.

### D-03 — Minor (not fixed, owner @frontend). Stale balance missing caption
`main.ts` `balanceBadge()`/`balanceAmount()` (L917–927), card cluster L992.
Design §3.2 requires the stale value to read «старый amount + подпись „последнее
успешное значение“». The badge «устарел · {age}» is present (meaning conveyed),
but the explicit caption is absent. Cosmetic; add a `.dim`/`title` when `freshness==="stale"`.

### D-04 — Minor (not fixed, owner @frontend). `change-ip` always sends `subnet_id:0`
`api.ts` L425–427: `{ subnet_id: subnetId || 0 }` sends `0` when the field is
blank, whereas spec §12 body is `{subnet_id?}`. Sending `0` may be read as subnet
0 rather than “provider default”. Contract-level nuance → surfaced, not changed.

### D-05 — Minor (not fixed, owner @frontend). 501 on change-ip/install uses code text, not the Beget banner
`main.ts` `doChangeIP()` L1593, `doInstallRes()` L1690. `create`/`replace` render
`BEGET_BANNER` (+`#/create` link) on `not_implemented` (L1484, L1763), but
change-ip/install render only «Действие пока не поддерживается на этом
провайдере.» (design §5 map). Honest and Russian (spec §22 allows “Beget banner
**or** degraded field”), but §15 asks for the same banner+link. Consistency nit.

### D-06 — Minor (not fixed, owner @frontend). `idempotency_conflict` on create does not reload
`main.ts` `submitCreateResource()` L1477–1479 regenerates the key and shows the
message but does not refresh the resources list (spec §22 «+ reload»).

### D-07 — Minor (not fixed, owner @frontend/@designer). Two §22/§7 presentation gaps
- `rate_limited` on verify (`doVerify` L1210–1211) shows the message but does not
  gate the submit until «Повторить» after `Retry-After` (spec §4/§22). Server still
  enforces the limit.
- The create form never renders the §7 degrade `.banner.info` («Каталог провайдера
  пока недоступен — заполните параметры вручную»); the form is free-text by design
  (catalog not called), so the notice is simply absent, not wrong.
- Neither `#hc-form-err`/`#cr-err` nor its fields get an `aria-describedby`
  (spec §3/§6.3); `role="alert"` still announces the error.
