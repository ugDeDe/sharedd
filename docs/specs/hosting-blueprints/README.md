оформляется задачей, а не объявляется уже исправленным.

## Границы поставки

Полный управляемый цикл VPS: подключение аккаунта → каталог/оценка → заказ →
установка → допуск в пул → наблюдение → смена IP/замена → подтверждённая
очистка. Управление по умолчанию **MANUAL**. Автоматизация допускается только
после явного выбора пользователем неизменяемой версии PROFILE.
Никаких пополнений баланса, фоновых покупок от одного факта бана или
произвольного HTTP-конструктора в v1.

## Открытые интеграционные ворота

- **Beget primary IPv4:** нет документированного promote-primary endpoint.
  Удаление старого основного адреса с сохранением добавленного требует
  отдельно разрешённого интеграционного подтверждения. До него профиль
  смены IP нельзя публиковать как проверенно работающий end-to-end.
- **Beget balance:** `getAccountInfo` относится к API виртуального хостинга.
  Поддержка VPS-only аккаунтов и соответствие cloud-расходам не подтверждены;
  валюта не документирована. Нельзя подписывать это значение «баланс VPS».
- **Nodehost:** документация помечена провайдером как предзапусковая;
  test-ключи read-only. Mock-тесты не доказывают фактический платный цикл.
- **Смена advertised IP:** требуется проверенная настройка `public_ip`,
  привязки прокси/маршрутов и SSH recovery на Beget; echo-сервис может
  продолжить видеть старый исходящий адрес.

Все ворота, условия публикации и тестовая матрица приведены в
[плане проверки](06-implementation-and-verification.md). Живые платные
вызовы требуют отдельного разрешения; при подготовке документов они не нужны.
