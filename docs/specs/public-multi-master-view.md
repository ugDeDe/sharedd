# specs/public-multi-master-view.md — несколько мастеров на один домен в UI

Ветка `dev`. Артефакт для реализации (`@frontend`) — **спека, не код**.
Общие правила (токены, копирайт, доступность, инвариант §8) — `DESIGN.md`.
Контекст мульти-мастеров — `docs/specs/multi-master-dns.md`. Эндпоинты —
`docs/api-contract.md` §6 (панель/статистика).

**Факты бэкенда (не противоречить):**

1. `GET /panel/api/overview` уже отдаёт:
   `domains:[…]` и `masters:[{domain, node_id, dead, ttl_sec, ttl_remaining_sec,
   masters:[{node_id, since, dead}], slots_filled:"2/2"}]`.
   Топология панели **может** рисовать все мастера домена правкой только
   фронта; сейчас она показывает лишь `m.node_id` (первый) — это разрыв.
2. `GET /statistics/api/list` (**публичный, без auth**) отдаёт только
   `{nodes:[…], quarantine:[…]}`. У ноды есть `master_domains`, `is_master`,
   `master_ttl_remaining_sec`. Нет агрегата по домену и нет `slots_total`
   публично.

## (a) Публичная `/statistics` — строки по домену (ссылке)

### Новое поле публичного API (минимальное, аддитивное)

`GET /statistics/api/list` → добавить необязательный ключ `domains`.
Форма (полная, перекрывает всё, что нужно UI):

```json
{
  "nodes": [ /* без изменений */ ],
  "quarantine": [ /* без изменений */ ],
  "domains": [
    {
      "domain": "cdn.example.com",
      "port": 443,
      "slots_filled": "2/2",
      "slots_total": 2,
      "masters": [
        {
          "node_id": "fra1-a1b2c",
          "ip_masked": "203.0.113.•••",
          "healthy": true,
          "ttl_remaining_sec": 4210
        },
        {
          "node_id": "ams2-d4e5f",
          "ip_masked": "198.51.100.•••",
          "healthy": false,
          "ttl_remaining_sec": -1
        }
      ]
    }
  ]
}
```

Правила полей:

| Поле | Тип | Смысл | Обязательно |
|---|---|---|---|
| `domain` | string | managed-домен (ссылка) | да |
| `port` | int | порт прокси (`shared_proxy.port`, обычно 443) | нет |
| `slots_filled` | string `"N/M"` | занято/всего слотов домена (как в overview) | да |
| `slots_total` | int | `M` = `masters_per_domain` | нет (дублирует `slots_filled`) |
| `masters[].node_id` | string | id ноды-мастера | да |
| `masters[].ip_masked` | string | **уже замаскированный** IP (тот же маскировщик, что в `nodes[].ip`) | нет |
| `masters[].healthy` | bool | жив ли слот (не `dead`) | нет |
| `masters[].ttl_remaining_sec` | int | остаток TTL слота; `≤0` — слот скоро переключится | нет |

`ip_masked` формирует **бэкенд** — фронт никогда не демаскирует и не
склеивает IP. Порядок `masters[]` не гарантирован; UI сортирует
«живые → мёртвые → по `node_id`».

### Деградация (совместимость со старым бэкендом) — обязательна

| Ответ | Поведение UI |
|---|---|
| ключа `domains` **нет** | карточка «Ссылки» **не рендерится вообще**; страница = текущий плоский список нод (байт-в-байт прежнее) |
| `domains: []` | карточка есть, внутри `.empty-state` «Доменов-ссылок нет» |
| у домена нет `masters` (или `[]`), но есть `slots_filled` | строка со счётчиком слотов, без чипов мастеров; TTL/статус скрыты |
| нет `port` | ячейка порта — `—` |
| нет `ip_masked` | чип: только `node_id` + статус, IP-часть отсутствует (без `?`) |

**Вывод:** старый бэкенд → `domains` отсутствует → весь код карточки
безопасно пропускается. Никаких запросов и ни одного нового цвета.

### Раскладка публичной страницы

В `renderListView()` (`ui/pages/stats/main.ts`) вставляем карточку
**между** баннером-инфо и карточкой «Ноды пула»:

```
.banner.info                                   (как сейчас)
section.card                                    ← НОВОЕ «Ссылки (домены)»
  .card-head h2 «Ссылки (домены)»
             .hint  single-summary «ссылок: N · мастеров: M · слоты: F/T»
  .table-wrap > table.table-cards
    thead: Домен · Порт · Мастера · Заполнено слотов
    tbody: одна строка на домен
section.card «Ноды пула»                        (как сейчас)
section.card.quarantine-card «Карантин»         (как сейчас)
```

Одна строка домена (`.table-cards`, `data-label` на каждой `td`):

| Колонка | Содержимое |
|---|---|
| **Домен** | `domain` — `.mono`, `nowrap`, `title` = полный домен |
| **Порт** | `port` — `.mono num`; нет значения → `—` |
| **Мастера** | чипы `.link-masters .chip` (см. ниже) + бейдж-счётчик «N мастеров» |
| **Заполнено слотов** | `slots_filled` в `.mono` + мини-`.meter` (fill `used/total`, класс `.ok` при полном, `.warn` при неполном) |

Чип одного мастера (переиспользуем `.chips .chip` из `badge.css`):

```
.label.link-master (жив → без «мёртв»)
  <span class="mono">{node_id}</span>
  <span class="badge ok">жив</span>            |  <span class="badge warn">мёртв</span>
  <span class="dim">⏱ {fmtDur(ttl_remaining_sec)}</span>   (если ttl_remaining_sec > 0)
```

Правила копирайта (русский операторский регистр, `DESIGN.md` §7):

- статус мастера — **только** «жив» / «мёртв»;
- `ttl_remaining_sec ≤ 0` → вместо таймера `переключение сейчас` (та же
  формулировка, что в публичном списке нод);
- «N мастеров» — числительное с корректной формой через `plural()`
  (`1 мастер · 2 мастера · 5 мастеров`);
- единый summary в `.hint`: «ссылок: {D} · мастеров: {M} · слоты: {F}/{T}»
  (F/T — сумма по доменам; опускаем при отсутствии данных).
- пустое `—` (em-dash), не «N/A».

Строка ноды с ролью «★ МАСТЕР» (`master_domains`) остаётся как есть —
новый блок **дополняет**, не заменяет плоский список.

### Состояния и доступность (WCAG 2.2 AA)

- loading: `.table-wrap` карточки — `.skeleton`-строки или `:empty` shimmer
  (как существующие карточки страницы).
- error: `.banner.bad` «Не удалось загрузить домены» + «Повторить»
  (не ломает уже отрисованный список нод).
- Таблица — семантическая `<table>` с `<thead>/<th>`; `data-label` для
  `.table-cards` на ≤720px.
- Статус мастера = **цвет и слово и (в `title`) причина** — не только цвет
  (`DESIGN.md` §10.5). Чип: `title` = `"{node_id} · {жив|мёртв} · TTL {…}"`.
- Клик по строке не вводим (домен не имеет отдельной публичной страницы) —
  строка не `.clickable`, курсор обычный.

### Мобайл

≤720px: `.table-cards` → карточки (существующий приём); чипы мастеров
переносятся, `data-label` даёт подписи. ≤640px: карточка на всю ширину.
Горизонтального скролла на 320px нет (чипы `flex-wrap`).

## (b) Панель — топология рисует все мастера домена

Источник — уже есть: `o.masters[].masters:[{node_id, since, dead}]` и
`slots_filled` (`docs/specs/multi-master-dns.md`, «Панель»). Правка только в
`ui/pages/panel/views/overview.ts` (`domainItemHTML`) + `panel/page.css`.

### Разметка карточки домена

Внутри `.topo-b` (домен + подпись) добавляем строку чипов слотов:

```
.topo-item (live|sick)
  .topo-b
    .topo-t {domain}
    .topo-s {A → ip1, ip2}                 ← все IP домена, а не первый
    .chips.topo-masters                    ← НОВОЕ
      .chip
        .mono {node_id}
        [.badge.warn «мёртв»]              (только если dead)
        .dim «с {fmtClock(since)}»
      …повтор на каждый слот…
  .topo-r
    .topo-n {slots_filled-occupied}         ← занятые слоты (число)
    .topo-u {«из N слотов»}                 ← slots_filled «occupied/total»
```

- `slots_filled` («2/2») **всегда видим** (в `.topo-r` или бейджем
  `.badge.mono` в `.topo-b`) — это требование задачи.
- Статус слота: живой — чип без бейджа (точка слева `::before` `--ok`);
  мёртвый — `.badge.warn` «мёртв» (тот же словарь, что в публичной части).
- `since` — `.dim`, `title` = полная метка (`fmtClock`).
- Домен без мастера (`node_id` пуст, не CNAME) — как сейчас `.sick`,
  подпись «мастер не назначен», чипов нет.

### Минимальный новый CSS (в `ui/pages/panel/page.css`, не в `components/`)

Пока класс нужен одной странице — живёт в `page.css` (`DESIGN.md` §5.2):

```css
/* карточка домена растёт под несколько слотов-мастеров */
.topo-item.has-masters { height: auto; min-height: 62px; align-items: flex-start; padding-top: 10px; padding-bottom: 10px; }
.topo-masters { margin-top: 6px; }
.topo-masters .chip { font-size: 11px; gap: 5px; padding: 2px 8px; }
```

Никаких новых цветов/радиусов: чипы — существующие `.chips .chip`, бейджи —
`.badge.ok/.warn`, разметка — существующие `.topo-*`.

### Связи (wires) — намеренное упрощение

Одна линия «домен → мастер» на домен сохраняется и ведёт к **первому
живому** мастеру (как сейчас). Остальные мастера показаны чипами в карточке
домена. Полный fan-out линий к каждому слоту **не** рисуем: это раздует
SVG-слой и координатную логику `drawTopologyLinks` без пользы для оператора.
`// ponytail: один wire на домен → первый живой мастер; fan-out, если
понадобится видеть все связи сразу.`

`drawTopologyLinks` при мульти-мастере получает `wired` по-прежнему (первый
`node_id`), высоты карточек измеряются `getBoundingClientRect` — растянутая
карточка домена не ломает координаты.

### Метрика «Мастера» → «Домены с мастером»

Текущее значение `aliveMs / active.length` считает **домены** (одна запись
`masters[]` = один домен), а подпись «Мастера» врёт: это отношение доменов,
не мастеров. Точная семантика:

- `domainsTotal = active.length` (активные домены, без CNAME-свёрнутых);
- `liveDomains` = активные домены, у которых **≥1 живой мастер**:
  `(m.masters||[]).some(x => !x.dead) || (m.node_id && !m.dead)`.

Точные строки плитки (`.metric`):

| Элемент | Значение |
|---|---|
| `.metric-label` | **`Домены с мастером`** (переименовано из «Мастера») |
| `.metric-value` | `{liveDomains}/{domainsTotal}` (напр. `12/14`) |
| класс значения | `.ok`, если `liveDomains === domainsTotal && domainsTotal > 0`, иначе `.bad` |
| `.metric-foot` | `домены с ≥1 живым мастером` + (если `folded>0`) ` · свёрнуто СРМД: {folded}` |

Копирайт: «живой мастер» = слот не `dead`. Не «активные назначения» —
формулировка неточна при N слотах на домен. Словарь статусов слотов
(«жив»/«мёртв») един для публичной страницы и панели.

### Доступность панели

- Чипы слотов — `<span class="chip">` с `title` `"{node_id} · {жив|мёртв} · с {время}"`;
  статус не только цветом.
- Карточка домена остаётся `data-pair` (подсветка пар при hover не
  меняется); доп. мастера не участвуют в подсветке.
- `@media (prefers-reduced-motion: reduce)` — переходы уже отключены в
  `topology.css`, новых нет.

## (c) Единый словарь новых терминов

| Понятие | Термин в UI |
|---|---|
| домен-ссылка (managed domain) | «ссылка» / «домен-ссылка» |
| слот домена (N слотов на домен) | «слот» |
| мастер одного слота | «мастер» (чип: `node_id`) |
| слот жив | «жив» |
| слот мёртв | «мёртв» |
| занято/всего слотов | `N/M` (напр. `2/2`) |
| домены с ≥1 живым мастером | «домены с мастером» |

Един для публичной `/statistics` и панели. Только эти слова — никаких
«реплика», «инстанс», «нода-мастер #2».

## Открытые вопросы (для @leader / backend)

1. **`port` в публичном `domains[]`** — отдавать ли `shared_proxy.port` в
   публичном ответе, или порт всегда 443 и колонку убрать? Предложение:
   отдавать, UI скрывает при отсутствии.
2. **`healthy` vs сырой `dead`** — публично отдаём инвертированный `healthy`
   (bool), или `dead` как в overview? Спека предполагает `healthy` для
   человекочитаемости; если backend отдаёт `dead` — фронт инвертирует.
3. **Сумма `slots_total` при неполном заполнении** — если `slots_filled`
   приходит строкой `"1/2"`, `slots_total` избыточен; предлагаю оставить
   оба (как в overview).
4. **`ip_masked` маскировщик** — подтвердить, что публичный маскировщик тот
   же, что для `nodes[].ip` (иначе два разных формата маски на одной
   странице).
