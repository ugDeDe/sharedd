# specs/multi-master-dns.md — несколько мастеров на один домен (DNS round-robin)

Контекст: `docs/api-contract.md` §6. Только registry-модуль. Задача —
несколько A-записей на managed-домен (по умолчанию поведение прежнее).

## Конфиг

```toml
[selection]
masters_per_domain = 1   # NEW; 1 = текущее поведение; >1 — round-robin из N живых мастеров
```

Валидация: 1..8. НЕ равно и не заменяет `[srmd] max_nodes_per_domain`.

## State и миграция

`Assignments map[string]string` → `map[string][]string` (упорядоченный список
nodeID, дубликаты запрещены). `AssignmentsSince` → `map[string][]time.Time`
(индексы совпадают со списком нод). Загрузка: старый формат (строка) читается
как список из одного элемента; сохранение — всегда новый формат.
`state_test.go` обновить, закрепив новый формат + обратное чтение старого.

## Селекция (`selection_core.go`, только чистые функции + тесты)

- Каждый домен имеет N слотов. Слот = (домен, индекс в списке).
- fillEmpty: свободные слоты заполняются из очереди (pickLeastLoaded),
  кандидат не должен уже держать этот домен и должен иметь IP, отличный от
  уже назначенных на домен (разные IP обязательны).
- reassignDead: живые держатели других слотов не трогаются; заменяется только
  слот с мёртвым/отсутствующим держателем.
- rotateByTTL: TTL считается ПО СЛОТУ (по AssignmentsSince[домен][i]);
  ротация заменяет один слот за тик, остальные не трогаются; держатель
  уходит в конец очереди как сейчас.
- Инвариант «пустая очередь не снимает назначения» сохраняется для всех слотов.
- События: master_elected/master_lost с полем Domain как сейчас + detail
  `slot i/N`.
- Тест-инвариант: srmdRequiredDomains(queue, maxPerDomain=5, M=2) == ceil(queue/10).

## DNS (`dns.go`)

- Новый reconcile: сверять полный набор IP домена с желаемым (порядок
  не важен): создать недостающие A, удалить лишние A, совпадающие не трогать.
  Удаление конфликтующих CNAME — как сейчас. `upsertARecord` (single) удалить
  или сделать частным случаем набора из одного IP.
- `DNSOperation.Desired*` поля → наборы: `DesiredTargets []string` + узел-ы
  `DesiredNodes []string`; миграция state аналогично Assignments (строка →
  список из одного). AppliedTargets аналогично.
- `recoverDNSDesiredLocked` строит наборы из мульти-назначений.
- `applyDNSTarget` → `applyDNSTargets(domain, []{nodeID, ip})`.
- Счётчики: один DNSEvents-цикл на домен как сейчас; событие detail
  `A -> ip1, ip2`.

## СРМД (`srmd.go`)

- Ёмкость одного домена масштабируется множителем мастеров:
  `domain_capacity = max_nodes_per_domain × masters_per_domain`.
  Пример (по требованию владельца): max_nodes_per_domain=5, M=1 → домен
  держит 5 нод очереди; M=2 → домен держит 10 нод очереди.
- `srmdRequiredDomains` считает делением размера здоровой очереди на
  `domain_capacity` (ceil, минимум 1). Fold/unfold-пороги используют ту же
  ёмкость. Число доменов при M>1 сокращается.
- Число клиентов домена = сумма клиентов всех назначенных мастеров
  (DomainClients обновлять агрегатом).
- Unfold возвращает домен под обычную мульти-селекцию.
- Анти-флап srmdStableTicks и потолок srmdMaxDomains — без изменений.

## Панель

- `/panel/api/overview`: для каждого домена список мастеров
  `{node_id, ip, since}` + `slots_filled: "2/2"`.
- Публичные страницы (stats/dashboard/links) — без изменений формата
  (ссылки остаются по одному на домен).

## terminate/карантин

- terminateNodeLocked: удалять ноду из всех слотов её доменов; DNS-сверка
  набора подтянет запись. Остальное — как сейчас.

## Тесты (минимум)

1. fill расставляет 2 разных ноды с разными IP; дубль IP не допускается.
2. смерть одного из двух мастеров — заменяется только его слот, второй жив.
3. TTL ротация одного слота за тик; AssignmentsSince каждого слота независимо.
4. миграция: старый state (строка) читается, сохраняется в новом виде;
   DNSOperation строка → список.
5. DNS reconcile: добавить недостающий, удалить лишний, не трогать верный.
6. `masters_per_domain=1` → поведение байт-в-байт прежнее (кроме формата
   хранения списков из одного элемента).
7. terminate при 2 мастерах: слот освобождается, второй остаётся мастером,
   DNS-набор уменьшается.
