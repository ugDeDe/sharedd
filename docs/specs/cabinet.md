# specs/cabinet.md — постраничные спеки: вход, кабинет, пользователи

Ветка `dev`. Артефакт для реализации. Общие правила (токены, копирайт,
доступность, секреты, инвариант «отказ ≠ пересоздание») —
`DESIGN.md` (корень). Эндпоинты — `docs/api-contract.md` §2, §2.1, §4
(авторитетны, здесь не переписываются).

Структура каждой страницы (uigen): `ui/pages/<page>/index.html` (каркас с
маркерами `<!--{css}-->` / `<!--{js}-->`), `page.css` (с `@import` частей
системы), `main.ts`. Образцы: `ui/pages/panel/` (полная), `ui/pages/links/`
(простая, с модалкой), `ui/pages/dashboard/`.

---

## Страница 1 — `signin` (вход и регистрация)

- Каталог: `ui/pages/signin/` · маршрут `/signin`
- Аутентификация: cookie `sharedd_session` (после успеха — редирект `/cabinet`)
- Оболочка: только `.topbar` (бренд) + `.auth-card`. Без навигации.

### Раскладка

```
.wrap.auth-wrap (max-width ~400px, центрирование по вертикали)
  header.topbar > .topbar-inner.glass   (бренд sharedd)
  .card.auth-card
    .card-head   → h2 «Вход в кабинет» + .hint «sharedd · аренда нод»
    .tabs        → два <button role="tab">: «Вход» | «Регистрация»
    form         → активная вкладка
    .card-foot   → submit + inline-ошибка
  .page-foot     → ссылка «← статистика пула»
```

### Компоненты

**Вкладки (`.tabs`)** — реализуется существующим паттерном segmented
(`.settings-nav`/`.chips`). `role="tablist"`, две кнопки `role="tab"` с
`aria-selected`, `aria-controls`. Переключение — без перезагрузки.

**Вкладка «Вход»** (дефолт):
- `input[type=text] name=username` `autocomplete="username"` `autocapitalize=off`
  `spellcheck=false` — label «Логин».
- `input[type=password] name=password` `autocomplete="current-password"` —
  label «Пароль», `.input-group` с `[data-reveal]`.
- `.btn.primary` «Войти» (полная ширина), блокируется на время запроса.
- Состояния: `idle` | `submitting` (disabled + текст «Вход…») |
  `error` (inline `.login-err`-стиль под формой + `role="alert"`).

**Вкладка «Регистрация»**:
- username + password + повтор пароля (только клиентская сверка).
- Подсказки `.field .help`: «3–32 символа: a–z, 0–9, `_ . -`»;
  «Пароль не короче 10 символов».
- После успеха: `.banner.info` «Аккаунт создан. Администратор выдаст квоту —
  до этого создать ноды нельзя.» + автопереход к вкладке «Вход» (или авто-вход,
  если backend ставит сессию).
- Состояния: `idle` | `submitting` | `error` (409 — «Логин уже занят»).

### API

| Действие | Метод/путь | Тело | Успех | Ошибки UI |
|---|---|---|---|---|
| Вход | `POST /api/auth/login` | `{username,password}` | 200 + cookie | 401 «Неверный логин или пароль»; 403 «Пользователь заблокирован» (`user_disabled`) |
| Регистрация | `POST /api/auth/register` | `{username,password}` | 200 | 400 «Логин: 3–32, a–z 0–9 _ . -» / «Пароль ≥ 10»; 409 «Логин уже занят»; 429 «Слишком много попыток, повторите позже» |
| Проверка сессии | `GET /api/auth/me` | — | 200 | 401 → остаёмся на вкладке |

CSRF: заголовок на мутациях (имя — см. `DESIGN.md` §11, п.2). При 401/403
сессии — не зацикливаться, показать форму.

### Валидация (клиент, дублирует сервер)

- username: `pattern="[a-z0-9_.-]{3,32}"`, `minlength=3 maxlength=32`.
- password: `minlength=10`.
- Регистрация: пароли совпадают (иначе inline «Пароли не совпадают»).
- Не отправлять пустые поля; фокус на первое невалидное.

### Responsive

≤640px: `.wrap` padding 12px, карточка на всю ширину, кнопки полной ширины.
Клавиатура мобильная не должна перекрывать submit (проверить `scroll-margin`).

## Страница 2 — `cabinet` (мой кабинет)

- Каталог: `ui/pages/cabinet/` · маршрут `/cabinet`
- Аутентификация: cookie `sharedd_session`. `GET /api/auth/me` при старте;
  `401` → редирект `/signin`.
- Оболочка: `.topbar` + верхняя навигация якорями (`#/nodes`, `#/create`,
  `#/beget`, `#/operations`) по паттерну панели; ≤720px — `.mobile-nav`.
  Плашка `.status-pill` — связь с регистратором.

### Навигация (якорные разделы, одна страница)

`#/nodes` «Мои ноды» · `#/create` «Создать сервер» · `#/beget` «Beget» ·
`#/operations` «Операции». Плюс в шапке: логин, «Выйти», переключатель темы.

### 2.1 Раздел «Мои ноды» (`#/nodes`)

**Данные:** `GET /api/auth/me` → шапка; `GET /api/me/nodes` → список.

**Сводка (`.metrics` / `.quota`)** — три метрики:
1. «Квота»: `used_nodes` / `max_nodes` (`.metric-value` + `.unit`), под ней
   `.meter` (fill: `.ok` <100%, `.warn` 100%, т.к. новая регистрация
   заблокирована). Foot: «занято мест».
2. «Нод в пуле»: число активных.
3. «Проблемы»: число нод с `dc2_ok=false` или `quarantine` (`.bad` при >0).

**Список нод** — `.node-list` > `.node-card` (как панель):
- Слева: `node_id` (`.mono`, `.node-id`) + `ip` (`.mono`).
- Справа: доступность (`.meter` с `.meter-value`) + `.node-side`.
- Чипы: `.checks` → `check-tag` «DC2» (`.ok`/`.bad`/`.unknown`), при
  `quarantine` — `.badge.warn` «карантин Globalping».
- `master_domains` непусто → `.node-card.master` + `.badge.gold` «мастер».
- Раскрытие `.node-more`: детали (`.kv`), домены-мастера, кнопка
  `.btn.danger` «Удалить ноду» → подтверждение `.modal`.

**Состояния:**
- loading: skeleton (`.node-list` c `.skeleton`-строками либо `:empty` shimmer).
- empty: `.empty-state` — «Пока нет нод. Создайте сервер в разделе
  «Создать сервер» — нода появится после регистрации в пуле.»
- error `GET /api/me/nodes`: `.banner.bad` «Не удалось загрузить ноды» +
  кнопка «Повторить».
- quota_at_max (used==max): под сводкой `.banner.warn` «Квота исчерпана:
  новая регистрация заблокирована. Освободите место или запросите лимит
  у администратора.»

**Если `dc2_ok=false`** — рядом с чипом причина (`DESIGN.md` §6.2) и
обязательная `.card-note`: «Отказ здоровья не пересоздаёт сервер — ресурс
остаётся для повторной установки». **Не** предлагать «пересоздать».

**API:** `GET /api/me/nodes`;
`DELETE /api/me/nodes/{node_id}` → 200 (нода уходит на удаление; место
**не** освобождается, пока не освободит админ) → тост «Нода отмечена на
удаление. Место освободит администратор.» Ошибки: 403 «Это не ваша нода»,
404 «Нода не найдена».

### 2.2 Раздел «Создать сервер» — визард (`#/create`)

Оформляется как `.card` с `.wizard` внутри. Шаги (`.wizard-steps`, активный
`--acc-soft`): **Регион → Тариф → Профиль → Переменные → Подтверждение**.

Предусловие: `GET /api/me/beget/link` `verified=true`. Иначе шаг 1 заменён
на `.banner.warn` «Сначала подключите аккаунт Beget» + ссылка на `#/beget`;
кнопки далее `disabled`.

**Шаг 1 «Регион»** — `GET /api/me/beget/regions`. Список карточек/`select`.
Состояния: loading (skeleton), empty (`.empty-state` «Каталог пуст»),
error (`.banner.bad` + «Повторить»).

**Шаг 2 «Тариф»** — конфигурации выбранного региона (`configuration_id`,
цена если отдаётся). Радио-карточки; выбор обязателен.

**Шаг 3 «Профиль»** — `GET /api/me/profiles` (только `published`). Список с
описанием; выбор обязателен.

**Шаг 4 «Переменные»** — форма по `vars_schema` профиля (required/типы,
неизвестные ключи не показываем и не отправляем). Валидация клиентская +
серверная. `.field .help` под каждым полем.

**Шаг 5 «Подтверждение»** — сводка выбранного (регион, тариф, профиль, vars)
`.kv`-таблицей; `.banner.warn`: «Списание с личного аккаунта Beget. Заказ
отправляется один раз.»; чекбокс `.check` «Подтверждаю создание» (обязателен).
Кнопка `.btn.primary` «Создать сервер» **disabled**, пока чекбокс не отмечен.

**Отправка:** `POST /api/me/vps` `{region, configuration_id, profile_id, vars,
confirm:true, idem_key}`.
- `idem_key` генерируется один раз на попытку (UUID), **не** меняется при
  сетевом ретрае — повтор с тем же ключом вернёт ту же операцию.
- Кнопка блокируется на время запроса; после ответа — переход в «Операции»
  с подсветкой новой операции.
- Ошибки: 400 (невалидный регион/vars) → `.banner.bad` у шага; 403
  `quota_exceeded` → «Квота исчерпана»; 429 лимит/cooldown → «Слишком часто:
  подождите <cooldown> перед следующим заказом»; 503 `users_disabled` /
  control-db → «Сервис временно недоступен».

**Инвариант:** визард никогда не предлагает «повторить создание» после
ошибки установки — только «повторить установку» (через операцию) или
«удалить». Повторный платный POST запрещён (`DESIGN.md` §8).

### 2.3 Раздел «Beget» (`#/beget`)

**Статус:** `GET /api/me/beget/link` → `{verified, last_error}`.
- `verified=true` → `.badge.ok` «подключён», дата проверки (если есть).
- `verified=false` и `last_error` → `.badge.bad` + текст `last_error`.
- не подключён → `.banner.info` «Подключите личный аккаунт Beget».

**Форма подключения:** `PUT /api/me/beget/link` `{login, password}`.
- Поля: `login` (`.mono`), `password` (`.input-group` + `[data-reveal]`).
- `.help`: «Пароль не отображается и не сохраняется в открытом виде.
  Регистратор добавит SSH-ключ для установки.»
- После успеха: **очистить поле пароля**; показать `.badge.ok` «проверено».
- Ошибки: 400 «Неверный логин или пароль», 403, 503 → `.banner.bad`.
  Секреты никогда не эхо в UI.

**Секреты:** login/password не показываются после отправки; SSH-ключ — только
факт «зарегистрирован».

### 2.4 Раздел «Операции» (`#/operations`)

**Данные:** `GET /api/me/operations` → `{id, kind, state, node_id?,
last_error, created_at}`. Автообновление (poll ~5s, как панель).

**Таблица** `.table-wrap > table.table-cards` с `data-label`:
`Создана` (fmtClock) · `Тип` (kind) · `Нода` (`.mono`) · `Состояние`
(бейдж §6.3) · `Ошибка` (`.wrap`, `last_error`) · `Действие`.

**`state=unknown`** — отдельная видимая строка: `.badge.special` «неизвестно ·
ручной разбор» + пояснение под таблицей (`.card-note`): «Ответ провайдера
потерян. Повторный платный заказ запрещён; регистратор сверяет ресурс у
провайдера. Если сверка не удалась, запись остаётся для ручного разбора —
создайте обращение к администратору с этим `id`.»

**Отмена:** `POST /api/me/operations/{id}/cancel` — доступна только для
незавершённых и **не** для оплаченных после `sent`. Кнопка `.btn.sm`:
- `pending`: «Отменить» активна.
- `sent`: disabled, `title` «Заказ уже отправлен провайдеру — отмена невозможна».
- прочие: кнопки нет.

**Состояния:** loading (skeleton), empty (`.empty-state` «Операций пока нет»),
error (`.banner.bad` + «Повторить»). Ошибки cancel: 404 «Операция не найдена»,
409 «Операцию нельзя отменить на этом шаге».

### 2.5 Раздел «Ключ доступа» (в шапке кабинета или отдельный блок `#/nodes`)

**Данные:** `GET /api/me/authkey` → `{prefix, created_at, active}`.
- Показ: `.kv` «Ключ» → `sda_XXXXXXXX…` (`.mono`), `.badge.ok` «активен» /
  `.badge` «отозван», «создан» → fmtAgo/clock.
- Кнопка `POST /api/me/authkey/rotate` (**эндпоинт-разрыв, см. `DESIGN.md`
  §11 п.1**) — до его появления кнопка скрыта, вместо неё `.hint`
  «Выпуск ключа — через администратора».
- **Одноразовый показ:** ответ rotate содержит полный ключ → открыть `.modal`
  с `.secret-reveal`: `.banner.warn` «Ключ показывается один раз. Сохраните
  его сейчас — позже он недоступен.», код в `.mono`, кнопка «копировать»
  (паттерн `copy()` из `links/main.ts`). Закрытие — ключ уходит из DOM.
- Предупреждение: «Новый ключ отзовёт все прежние. Существующие ноды
  продолжат работу; новые регистрации старым ключом будут отклонены.»

### Responsive (кабинет)

- ≤720px: `.table-cards` → карточки; `.node-card` в одну колонку
  (как в `panel/page.css`); `.mobile-nav` из 4 иконок.
- ≤640px: метрики 2 в ряд, `.wrap` padding 12px.
- Визард: `.wizard-steps` горизонтально со скроллом или вертикально;
  кнопки навигации полной ширины.

## Страница 3 — административное управление пользователями (`admin-users`)

**Решение:** это **вид существующей панели**, а не отдельная страница.
Причина: эндпоинты под `Bearer panel.token` (§2), уже есть оболочка,
навигация, авторизация, тосты, модалки. Дублировать панель — лишний код.

- Файл: `ui/pages/panel/views/users.ts` (+ регистрация в `main.ts`:
  `VIEW_META.users`, роут `#/users`, `nodes.init`-подобный `users.init`).
- Навигация: пункт «Пользователи» в `.nav` и `.mobile-nav` панели.
- Заголовок: `h1.view-title` «Пользователи».

### Раскладка

```
section.view#view-users
  .card
    .card-head → h2 «Пользователи» + .hint «квота, ключи, освобождение мест»
                 + .btn.primary «Создать пользователя»
    .table-wrap > table.table-cards
      thead: Логин · Роль · Квота · Занято · Статус · Действия
      tbody#users-body
  (форма создания — в .modal или инлайн-карточке)
```

### Данные и действия

| Действие | API | UI |
|---|---|---|
| Список | `GET /panel/api/admin/users` → `{users:[{id,username,role,max_nodes,used_nodes,disabled}]}` | строки таблицы |
| Создать | `POST /panel/api/admin/users` `{username,password,role?,max_nodes?}` → 200 / 400 / 409 | модалка «Создать пользователя» |
| Правка | `PATCH /panel/api/admin/users/{id}` `{max_nodes?,disabled?,password?}` | инлайн-редактор квоты, тумблер «заблокирован», сброс пароля |
| Выпустить ключ | `POST /panel/api/admin/users/{id}/authkey/rotate` → `{authkey}` | `.modal` одноразового показа |
| Отозвать ключ(и) | `DELETE /panel/api/admin/users/{id}/authkey` → 204 | подтверждение |
| Освободить ноду | `POST /panel/api/admin/users/{id}/release-node` `{node_id}` → 200 | в раскрытии строки, ввод/выбор `node_id` |

### Строка пользователя (`.table-cards`)

- `username` (`.mono`? нет — логин человеческий; `.mono` для `node_id`).
- Роль — `.badge` «админ» (`.special`/`gold`) / «пользователь» (нейтр.).
- Квота: `max_nodes` (число, `.num`). Инлайн-правка: клик → `input[type=number]`
  `min=0 max=10000` + «Сохранить»/«Отмена» (`PATCH`).
- Занято: `used_nodes` + мини-`.meter` (used/max).
- Статус: `.badge.ok` «активен» / `.badge.bad` «заблокирован».
- Действия: `.btn.sm` «Ключ» (rotate) · `.btn.sm` «Отозвать» (danger, если
  ключи есть) · `.btn.sm.ghost` «Освободить место» · «Сбросить пароль».

**Правила (из контракта):**
- Нельзя заблокировать/разжаловать последнего активного админа — сервер
  вернёт 400/409; UI показывает тост «Нельзя заблокировать последнего
  администратора» и откатывает тумблер.
- `max_nodes` вниз не удаляет ноды, только блокирует новые регистрации —
  подсказка `.hint` у редактора: «Уменьшение не удаляет существующие ноды,
  но блокирует новые сверх лимита.»
- `release-node` нужен, когда нода удалена физически: место освобождается,
  владелец переходит в legacy.
- Дубль username → 409 «Логин уже занят».

### Состояния

- loading: skeleton-строки / `:empty` shimmer.
- empty: `.empty-state` «Пользователей нет. Создайте первого.»
- error `GET`: `.banner.bad` + «Повторить».
- Мутации: кнопка disabled на время; успех — `showToast`; ошибка — `.err` тост.
- Одноразовый показ ключа — `.secret-reveal` (как в кабинете).

### Responsive

≤720px: таблица → карточки (`.table-cards`), действия — в раскрытии строки
(`.node-more`-подобный), кнопки полной ширины.

## Сквозные требования (обе новые страницы + вид панели)

- `page.css` новых страниц: `@import` `tokens.css`, `base.css`, и
  используемые `components/*` (glass, topbar, card, table, badge, form,
  feed, misc). Свой CSS — только раскладка.
- `main.ts`: `initTheme()`, `esc()` для любого интерполяции пользовательских
  данных (username, node_id, last_error, домены), `$()` для доступа.
- Никаких `innerHTML` с неэкранированными данными (XSS).
- Все мутации session-cookie API шлют CSRF-заголовок; `401` → `/signin`.
- Автообновление кабинета — опрос раз в 5 с (как панель), плавно, без
  сброса фокуса/скролла; на скрытой вкладке (`document.hidden`) — пауза.
- Тост — `#toast` (`DESIGN.md` §5.1); статусные анонсы — `aria-live`.
- Тексты — по `DESIGN.md` §7; инвариант `DESIGN.md` §8 присутствует на
  `#/nodes`, `#/create`, `#/operations`.
