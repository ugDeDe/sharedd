# addendum-manual-servers.md — свой токен нод и подключение своих серверов

Ветка `dev`. Дополняет `invitations-migration-contract.md` и
`addendum-profiles-vps.md`. Решения обязательные.

## 1. Свой токен (authkey) — один на все VPS

Модель уже такая: `authkeys` — ключ на ПОЛЬЗОВАТЕЛЯ (не на ноду), все его ноды
используют один ключ.

- `POST /api/me/authkey/rotate` (сессия+CSRF) → `{authkey}` — полный ключ
  показывается ОДИН раз; все прежние ключи пользователя отзываются
  (уже есть в control: rotate revokes all).
- `DELETE /api/me/authkey` → 204, все ключи пользователя отозваны (существующие
  ноды продолжают работать; новые регистрации с ключом — нет).
- `GET /api/me/authkey` без изменений: `{prefix, created_at, active}`.
- UI: раздел «Ключ доступа» — кнопки «Выпустить/перевыпустить» и «Отозвать»,
  одноразовый показ с копированием, явное предупреждение: «перевыпуск
  немедленно отзывает старый ключ; ноды, которые ещё не зарегистрированы с ним,
  потребуют новый».

## 2. Свои серверы (без Beget)

Пользователь подключает уже существующий сервер: `IP` + пароль **или** свой
SSH-ключ. Провайдер не участвует, платных вызовов нет.

Таблица `manual_hosts(id PK, user_id, label, host, port, ssh_user,
auth_type TEXT CHECK(auth_type IN ('password','key')), secret_enc BLOB NOT NULL,
created_at, verified_at, last_error)`.

Эндпоинты (сессия+CSRF, владелец обязателен):
- `GET /api/me/servers` → список (без секретов): `{id,label,host,port,ssh_user,
  auth_type,created_at,verified_at,last_error,node_id?,operation?}`.
- `POST /api/me/servers` `{label,host,port?,ssh_user?,password?|private_key?}` →
  201. Валидация: `host` — публичный IPv4 (запрещены loopback/private/link-local
  и IP самого регистратора), `port` 1..65535 (дефолт 22), `ssh_user` дефолт
  `root` (шаблон `[a-z_][a-z0-9_-]{0,31}`), ровно ОДНО из `password|private_key`;
  `private_key` — валидный PEM/OpenSSH private key ≤ 16 KiB. Секрет шифруется
  AES-GCM (`master.key`), наружу не отдаётся никогда, в логи не попадает.
- `POST /api/me/servers/{id}/install` → операция `manual_install`: резервирует
  место в квоте (одно на сервер), создаёт предсозданную личность ноды
  (`node_id`+`node_secret`) и запускает выбранный профиль (шаги по SSH).
  Провайдерские вызовы запрещены. Повтор — тот же `retry-install`
  (та же нода, ноль новых серверов).
- `DELETE /api/me/servers/{id}` → удаляет запись, освобождает место
  (нода остаётся в пуле; отдельное удаление ноды — существующим механизмом).
- `POST /api/me/servers/{id}/check` (опционально) → проверка SSH-доступа и
  версии ОС без установки; результат в `verified_at`/`last_error`.

Общее с Beget:
- Тот же профиль/шаги и тот же `Executor` (SSH). Отличие только в источнике
  сервера: `beget` (платный заказ) vs `manual` (готовый хост).
- Тот же инвариант: `done` только после подтверждённой регистрации ноды
  (`/api/node/status`), шаги с `bash -eo pipefail -s`, abort на первой ошибке.
- Секреты сервера (пароль/ключ) — только в `secret_enc`; ни один read-эндпоинт
  их не возвращает; в `operations.output` маскируются.

## 3. UI

Кабинет: раздел **«Свои серверы»** — форма (label, host, port, user, выбор
«пароль»/«ключ», поле или загрузка файла ключа), список с состоянием
(nовый/проверен/устанавливается/готов/ошибка), действия «Установить»,
«Повторить установку» (никогда не «купить заново»), «Удалить». Секреты: ключ —
файл или вставка, после отправки поле очищается; пароль не показывается.

## 4. Тесты (обязательные)

1. `POST /api/me/authkey/rotate` — новый ключ, старый немедленно недействителен;
   `DELETE` отзывает; чужой ключ не затрагивается.
2. Валидация сервера: private/loopback/registry IP, порт 0/70000, оба секрета
   сразу, ни одного секрета, битый ключ, ключ > 16 KiB → 400 с внятной причиной.
3. `install`: место в квоте занято один раз; повторный install на том же сервере
   не создаёт второго слота; `retry-install` — ноль провайдерских вызовов.
4. Секреты: ни пароль, ни ключ не появляются в ответах, логах и
   `operations.output`.
5. Шаги выполняются тем же executor'ом с инъекцией `node_secret`; сервер
   регистрируется (мок).
6. Удаление сервера освобождает место; нода в пуле не затрагивается.
