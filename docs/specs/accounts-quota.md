# specs/accounts-quota.md — поведение M1: пользователи, authkey, квоты

Контракт: `docs/api-contract.md`. Ниже — поведенческие детали, не покрытые
контрактом.

## Жизненный цикл

- Создание пользователя → выдача authkey (rotate) — админом через панель.
  Ключ показывается один раз; повторно — только новый rotate.
- Регистрация ноды с ключом → `node_owners` + место в квоте. После prune /
  expiry / terminate владелец сохраняется; место продолжает считаться
  занятым (админ освобождает через release-node).
- Отзыв ключа: существующие ноды остаются; новые регистрации с этим ключом —
  403. Rotate инвалидирует все старые ключи пользователя.
- Блокировка пользователя: ноды продолжают работать (heartbeat/report не
  отклоняем — не ломаем трафик пользователей пула), новые регистрации 403.

## Границы

- Не трогаем: селекцию мастеров, СРМД, DNS, terminate/reverify, health-лестницы.
- `users.enabled=false` → полная обратная совместимость (текущее поведение).
- Тесты обязательны: два конкурентных POST /register при одном свободном
  месте (ровно один 200), чужой authkey, повторная регистрация своей ноды,
  повторная регистрация чужой ноды (owner_mismatch), max_nodes вниз → новые
  регистрации отклонены, release-node → место свободно, рестарт регистратора
  (перезагрузка state) сохраняет владельцев.
- Fail-closed: unit-тест «control.db открыть не удалось → /register 503 при
  users.enabled=true; при users.enabled=false регистрация работает как раньше».
