# plan-ui-batch.md — план правок UI/админки и переноса из mtplane

Источник-образец: `../mtplane` (серверный рендер, `internal/web/templates/*.html`,
роуты в `internal/web/server.go`: `/`, `/nodes`, `/nodes/{id}`, `/groups`,
`/providers`, `/profiles`, `/api/nodes/{id}/{checks,metrics,telemt,status}.json`,
`/api/dashboard.json`).

## Фаза 1 (сейчас)

1. Пользователь может **переименовать свою копию профиля** (кабинет, PUT
   `/api/me/profiles/{id}` принимает `name`; поле «Имя» редактируемое).
2. **Копии пользователей не показываются в админке** — админ видит только
   системные/опубликованные профили (created_by=0), свои копии юзеры видят
   только у себя.
3. **Дефолтная квота** `[users] default_max_nodes` (admin-настраиваемое), новый
   пользователь получает её при регистрации вместо 0 (0 = старое поведение).
4. **Удаление пользователя целиком** (админ): `DELETE /panel/api/admin/users/{id}`
   — с проверкой «последний админ», освобождением его нод (owner → legacy),
   удалением ключей/сессий; ноды не удаляем физически.
5. Вкладки **«Создать сервер» + «Свои серверы» объединить** в один раздел
   (список + кнопка «Добавить сервер»); **«Beget» → «Хостинги»** (одна вкладка,
   внутри — Beget; задел под других провайдеров).

## Фаза 2 — статистика нод из mtplane (перенос по разделам `node.html`)

Детальная карточка ноды: `GET /api/me/nodes/{id}/detail` + вид `#/nodes/<id>`
в кабинете (`ui/pages/cabinet/node-detail.ts`). Разделы без источника приходят
null, их имена — в `absent[]`; UI рисует «нет данных», не выдумывая значения.

1. ✅ Параметры ноды, доступность за 7 дней (дневные столбики), история IP
   (таблица, IP маскированы), последние проверки.
2. ✅ Хостинг (сеть ingress/egress; CPU/RAM — «нет данных»), соединения 24ч
   (текущие gauge + спарклайн writers), уникальные IP по пользователям
   (трафик по пользователям — «нет данных»).
3. ✅ Статистика telemt (`metrics_snapshot` — сводка + сворачиваемая таблица);
   DC и endpoints / качество/здоровье — «нет данных» (`telemt_control_api` нет).
4. ✅ События ноды (лента). Действия ноды (проверка/конфиг/переустановка) —
   «нет данных» (не реализованы); удаление ноды перенесено в шапку детали.

Отличие от mtplane: метрики берём из наших источников (`/statistics/api/node`,
`/report`, metrics_snapshot), не из его БД.

## Фаза 3 — история операций как в mtplane

- ✅ Пошаговое отображение операции (шаг, статус, длительность), раскрывающийся
  лог каждого шага: `operation_steps` (server) → `steps[]` в
  `GET /api/me/operations` → «Шаги (N)» в кабинете (`ui/pages/cabinet/main.ts`).
- Модальная вёрстка `node.html` не переносилась: использован тот же приём
  сворачиваемого лога (`<details>`), без нового кода модалки.
