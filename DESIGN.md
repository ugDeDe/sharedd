# DESIGN.md — sharedd web UI: вход, кабинет, управление пользователями

Ветка `dev`. Артефакт для реализации (`@frontend`). Авторитетные источники:

- `AGENTS.md` → «UI Generation»: `ui/pages/<page>/{index.html,page.css,main.ts}`,
  сборка `tools/uigen` → `registry/internal/webassets/<page>.html`.
  **Ванильный HTML + CSS + TS. Не Nuxt/React. Правки webassets/ запрещены.**
- `docs/api-contract.md` §2, §2.1, §4 — эндпоинты (не переписываются здесь).
- `docs/specs/beget-provisioning.md`, `docs/specs/accounts-quota.md`,
  `docs/specs/dc2-health.md` — поведение и инварианты.
- `ui/tokens.css`, `ui/base.css`, `ui/components/*.css` — существующая система.

Этот документ описывает **токены, компоненты, копирайт, доступность**.
Постраничные спеки — `docs/specs/cabinet.md`.

## 1. Архитектура и жёсткие ограничения

| Ограничение | Следствие для дизайна |
|---|---|
| uigen собирает `page.css` (с `@import`) + `main.ts` в один HTML | Страница = каталог с тремя файлами; `page.css` первым делом импортирует нужные части системы |
| Тёмная тема базовая (`data-theme="dark"`), светлая — опция | Цвета берём только из токенов; ни одного «сырого» hex в странице |
| `panel/` — админ-панель с `Bearer panel.token` (`localStorage`) | Раздел «Пользователи» — **вид панели**, не отдельная страница (та же авторизация) |
| Кабинет — session-cookie `sharedd_session`, CSRF double-submit | Вход/кабинет — отдельные страницы под cookie-аутентификацией, не панель |
| Секреты по контракту не отражаются в API | Полный authkey — только один раз в ответе rotate/create; в UI — только префикс |

**Правило нулевого дублирования:** ни одна страница не заводит собственную
шапку, карточку, кнопку, поле, бейдж, таблицу. Всё — из `ui/components/*.css`.
Новый CSS страницы — только раскладка (сетки/отступы), не «новые кнопки».

### Карта страниц

| Каталог | Маршрут (mount в Go-муксе) | Аутентификация | Оболочка |
|---|---|---|---|
| `ui/pages/signin/` | `/signin` | cookie | минимальная (без боковой навигации) |
| `ui/pages/cabinet/` | `/cabinet` | cookie | шапка + верхняя навигация (как links/dashboard) |
| `ui/pages/panel/views/users.ts` | панель `#/users` | `panel.token` | существующая панель |

> Директория страницы ≠ URL (`stats/` → `/statistics`). Реальный путь задаёт
> мукс сервера. Имена каталогов выше — предлагаемые; мусорные имена менять
> нельзя без правки мукса.

## 2. Токены

**Используем `ui/tokens.css` без изменений.** Ни одного нового цветового
токена: семантика уже покрыта (`--ok/--warn/--bad/--info/--special/--gold` +
`-soft`). Если для новых состояний не хватает смысла — берём ближайший
существующий, а не добавляем оттенок.

### 2.1 Поверхности и текст

| Токен | Назначение в новых экранах |
|---|---|
| `--bg` | фон страницы |
| `--surf` | карточка, строка-объект (нода, операция, пользователь) |
| `--surf-2` | шапка карточки, поле ввода, подвал карточки, hover строки |
| `--surf-3` | дорожка метра, скелет, счётчик `nav-count` |
| `--line` / `--line-2` | границы блоков / внутренние разделители |
| `--fg` | основной текст и значения |
| `--fg-2` | подписи, вторичный текст, label |
| `--fg-3` | подсказки, мета, «dim», placeholder |

### 2.2 Семантика состояний (единственное место смысла)

| Токен | Смысл | Где применять |
|---|---|---|
| `--ok` | здорово / подтверждено / активно | нода здорова, операция `confirmed`, ключ активен, Beget `verified` |
| `--warn` | внимание, требует действия, неизвестно | карантин, операция `unknown`/`pending`/`deleting`, «ждёт проверки» |
| `--bad` | отказ / ошибка | нода нездорова, операция `failed`, ошибка связи с Beget |
| `--info` | нейтральный процесс | операция `sent`, режим fallback-метрик |
| `--special` | ручной разбор (человек) | строка `unknown` с пояснением |
| `--gold` | мастер домена | только маркировка мастерства (как в панели) |
| `--acc` | главное действие, активная вкладка | одна primary-кнопка на секцию |

### 2.3 Расширенные токены (уже есть — используем, не дублируем)

`--acc-soft` (фокус, активная вкладка), `--bad-soft/--warn-soft/--ok-soft/
--info-soft` (фоны бейджей/баннеров), `--r-xs…--r-xl/--r-pill`,
`--ctl-h` (34px), `--gap` (14px), `--pad` (18px), `--sh-1/--sh-2/--sh-pop`,
`--track/--track-in/--thumb` (сегментированные переключатели).

## 4. Сетка, отступы,控件

- `--gap` 14px между карточками/секциями, `--pad` 18px внутри карточек.

## 6. Состояния и их визуальный словарь

### 6.1 Нода (`GET /api/me/nodes`)

| Условие | Бейдж | Класс | Показ |
|---|---|---|---|
| `availability` ок и `dc2_ok=true` | «здорова» | `.badge.ok` | полный метр доступности |
| `dc2_ok=false` | «DC2: <причина>» | `.badge.bad` | + `check-tag.bad` «DC2», причина из §6.2 |
| `quarantine` присутствует | «карантин Globalping» | `.badge.warn` | + строка-пояснение, **не бан** |
| нет данных/`status` неизвестен | «нет данных» | `.badge` (нейтр.) | `check-tag.unknown` |
| мастер доменов (`master_domains`) | «мастер» | `.badge.gold` | левая золотая кромка `.node-card.master` |

Строка ноды: `.node-card` (как в панели), СЛЕВА id+IP (`.mono`), СПРАВА
доступность (`.meter`), снизу `check-tag` DC2/карантин. Клик — раскрыть
`.node-more` (детали + «удалить ноду» `DELETE /api/me/nodes/{id}`).

### 6.2 Причины DC2 (`dc2_reason`, см. dc2-health.md)

Тексты (не менять смысл): `dc2_api_error` → «нет ответа API», `dc2_me_disabled`
→ «ME-пул выключен», `dc2_stale` → «снимок устарел», `dc2_absent` → «нет DC2»,
`dc2_no_endpoints` → «нет endpoints», `dc2_no_fresh` → «нет живых writers»,
`dc2_fallback_metrics` → «режим совместимости». **Рядом всегда:** «отказ
здоровья не пересоздаёт VPS» (см. §8).

### 6.3 Операция (`state`)

| state | Бейдж | Класс |
|---|---|---|
| `pending` | «ожидает» | `.badge.info` |
| `sent` | «отправлено провайдеру» | `.badge.info` |
| `confirmed` | «подтверждено» | `.badge.ok` |
| `unknown` | «неизвестно · ручной разбор» | `.badge.special` (или `.badge.warn`) |
| `failed` | «ошибка» | `.badge.bad` |
| `deleting` | «удаляется» | `.badge.warn` |
| `deleted` | «удалено» | `.badge` (нейтр.) |

Для `unknown` — поясняющая строка: «Ответ провайдера потерян. Повторный
платный заказ запрещён; регистратор сверяет ресурс и оставит запись для
ручного разбора, если сверка не удалась».

### 6.4 Ключ доступа / Beget

- `active=true` → `.badge.ok` «активен»; иначе `.badge` «отозван».
- Beget `verified=true` → `.badge.ok` «подключён»; `last_error` присутствует
  → `.badge.bad` «ошибка» + текст `last_error`.

## 7. Копирайт: русский продуктовый регистр

### 7.1 Тон

- **Операторский, плотный, без маркетинга.** Никаких «Легко и просто»,
  «Всё под контролем», эмодзи, восклицаний.
- Технический сленг пула уместен: нода, пул, мастер, аутки, квота, карантин,
  СРМД. Не переводить на «человеческий» язык в ущерб точности.
- Никаких обещаний, которых API не даёт: «пересоздаст», «починит» — запрещены.

### 7.2 Термины (единообразие)

| Понятие | Термин в UI |
|---|---|
| authkey | «ключ доступа» (в подписи), значение — в `.mono` |
| max_nodes | «квота» / «мест» |
| used_nodes | «занято» |
| quota_exceeded | «Квота исчерпана: освободите место или увеличьте лимит» |
| quarantine | «карантин» |
| домен-ссылка (managed domain) | «ссылка» / «домен-ссылка» (мульти-мастер: `public-multi-master-view.md`) |
| слот домена (N на домен) | «слот», занято/всего — `N/M` |
| слот жив / мёртв | «жив» / «мёртв» |
| домены с ≥1 живым мастером | «домены с мастером» (плитка, ранее «Мастера») |
| dc2_ok=false | «DC2 недоступен: <причина>» |
| owner_mismatch | «Нода зарегистрирована другим пользователем» |
| user_disabled | «Пользователь заблокирован» |
| bad_authkey | «Ключ недействителен или отозван» |
| unknown (операция) | «Неизвестно — нужен ручной разбор» |
| release-node | «Освободить место» |

### 7.3 Формулировки кнопок и ошибок

- Кнопки — глагол в инфинитиве: «Войти», «Создать пользователя»,
  «Освободить место», «Отозвать ключ», «Повернуть ключ» (rotate →
  **«Выпустить новый ключ»** предпочтительнее: «повернуть» непонятно).
- Опасные действия — `.btn.danger` и подтверждение в `.modal` с явным
  названием объекта: «Отозвать ключ пользователя `ivan`? Существующие ноды
  продолжат работу; новые регистрации с этим ключом будут запрещены.»
- Ошибки — что произошло + что делать, без кода наружу (код — в `title`):
  «Квота исчерпана: освободите место» (`title="quota_exceeded"`).
- Пустые состояния — что здесь появится и как: «Пока нет нод. Создайте VPS
  в мастере ниже — нода появится после регистрации в пуле.»
- Неизвестные/недоступные значения — `—` (em-dash), не «N/A».

## 8. Инвариант «отказ ≠ пересоздание» (обязателен к показу)

Ни один экран не должен намекать, что ошибка здоровья/установки создаёт
новый VPS. В кабинете, на строке ноды, в списке операций и в визарде
размещаем один и тот же смысл (можно как `.card-note` / `.banner.info`):

> «Ошибка здоровья или установки не создаёт новый сервер. Ресурс остаётся и
> доступен для повторной установки профиля. Платный заказ отправляется
> ровно один раз — повтор того же запроса не создаёт второй сервер.»

Запрещены **утвердительные** формулировки, обещающие пересоздание/автоповтор:
«пересоздаст», «заменит ноду», «автовосстановление», «автоповтор разрешён».
Наоборот, **отрицания** этого же действия — часть самого инварианта и
разрешены: «отказ здоровья не пересоздаёт VPS» (§6.2), «Повторный платный
заказ запрещён» (§6.3), «повторный платный POST запрещён». Кнопка удаления
VPS — только явная, с подтверждением и оговоркой, что удаление ждёт
подтверждения провайдера.

## 9. Секреты (никогда не показывать, где запрещено)

| Что | Правило |
|---|---|
| Полный authkey | Только в ответе rotate (админ/кабинет) и только один раз. В UI — `.secret-reveal` с явной пометкой «показывается один раз, сохраните сейчас». После закрытия/перезагрузки — недоступен. |
| Префикс ключа | `sda_XXXXXXXX…` в `.mono`, всегда с многоточием. |
| Beget login/password | **Никогда** не выводим. Форма connect хранит значения только в памяти до отправки; после `PUT` поле пароля очищается. |
| SSH-ключ | Не выводим. Признак — только «ключ зарегистрирован» / `verified`. |
| Cookie/CSRF токен | Не выводим, не логируем. |

Никаких «показать пароль» для чужого аккаунта; для полей ввода пароля —
только `.input-group .in-btn[data-reveal]` (как в панели).

## 10. Доступность (WCAG 2.2 AA) — обязательные требования

1. **Семантика:** навигация — `<nav>`, действия — `<button>`/`<a>`,
   таблицы — `<table>` с `thead`/`th`; переключатель входа — `<button
   role="tab">` в `<div role="tablist">` с `aria-selected` и `aria-controls`.
2. **Метки:** каждое поле — `<label for>` (или `aria-label` для иконочных
   кнопок). Ошибки связаны `aria-describedby`; при невалидной отправке фокус
   — на первое невалидное поле.
3. **Фокус:** видимый `:focus-visible` (есть в базе). Модалка ловит фокус
   (`role="dialog"` `aria-modal="true"`), Escape закрывает, фокус возвращается
   на кнопку-инициатор. `preventScroll` при программном фокусе (как в
   `state.ts`).
4. **Контраст:** текст `--fg-2/--fg-3` на `--surf/--bg` — только для мета;
   смысловой текст — `--fg`. Бейджи `.badge.*` используют пару `-soft` фон +
   цвет ≥ 4.5:1; не полагаться только на цвет — рядом иконка/текст
   (`<i>`-точка + слово, как в существующих бейджах).
5. **Не только цвет:** состояние ноды/операции = цвет **и** текст **и**
   (где уместно) `check-tag`. Иконочные кнопки имеют `aria-label` и `title`.
6. **Формы:** `autocomplete` корректный (`username`, `current-password`,
   `new-password`); пароль ≥ 10 символов — подсказка и `minlength`;
   username-паттерн `[a-z0-9_.-]{3,32}` — `pattern` + `inputmode`.
   Кнопка submit блокируется на время отправки (`.btn[disabled]`).
7. **Состояния загрузки/ошибки/пусто:** у каждой значимой области есть
   визуальный «скелет» или `.empty-state`; ошибка — `.banner.bad`/тост;
   статусные изменения анонсируются через `aria-live="polite"` (тост,
   результат операции).
8. **Живые обновления:** автообновление кабинета — не чаще, чем нужно;
   скролл-позиция и фокус не сбрасываются (обновляем in-place, как панель).
9. **Клавиатура:** все действия достижимы Tab/Enter/Space; сортировка/фильтры
   в таблицах — через фокусируемые чипы/кнопки, не только мышь.
10. **Зум/рефлоу:** без горизонтального скролла на 320px; широкие таблицы —
    `.table-cards` → карточки на ≤720px.

## 11. Открытые вопросы (для @leader / backend)

1. **Самостоятельный rotate ключа в кабинете.** Контракт §2.1 даёт
   `GET /api/me/authkey`, но **не даёт** пользовательского rotate.
   Нужен `POST /api/me/authkey/rotate` (аналог админского, с owner-проверкой)
   и, возможно, `DELETE /api/me/authkey`. До появления — кнопка только у админа.
2. **CSRF: имена cookie и заголовка** не заданы в контракте (обычно
   cookie `csrf` / заголовок `X-CSRF-Token`). Уточнить у backend; UI читает
   cookie на старте и шлёт заголовок на всех мутациях.
3. **`/api/me/profiles` форма ответа** (поля профиля/версии, `vars_schema`)
   — по контракту только «published-профили». Нужен точный JSON для рендера
   формы vars.
4. **`/api/me/beget/regions` форма** (регионы → тарифы → `configuration_id`,
   цена) — для шага «тариф» и подтверждения стоимости.
5. **Цена/валюта в подтверждении заказа**: контракт не описывает поля
   стоимости; подтверждение требует явной суммы. Если API не отдаёт цену —
   показываем только выбранные параметры и текст «списание с личного
   аккаунта Beget», без выдуманных сумм.
6. **Маршруты/маунт новых страниц** в Go-муксе (`/signin`, `/cabinet`) и
   добавление пункта «Пользователи» в навигацию панели — вне UI-фазы, но
   нужны для ссылок.
7. **Пароль пользователя в админке**: `PATCH .../{id}` принимает `password`
   — уточнить, обязателен ли он при сбросе и есть ли отдельный ответ.

## 12. Definition of Done для @frontend (ссылка)

- Только токены/классы из этого документа и `ui/`; ноль новых цветов/радиусов.
- Каждая область: loading (skeleton/`:empty`), empty (`.empty-state`),
  error (`.banner`/тост), disabled (`.btn[disabled]`).
- Монospace для node_id/IP/доменов/id операций/префикса ключа.
- Инвариант §8 присутствует на кабинете и визарде.
- Полный authkey — только в одноразовом `.secret-reveal`.
- Клавиатурная доступность, фокус-менеджмент модалок, `aria-live` для тостов.
